## 1. Диагноз по фидбеку (что именно болит)

| Симптом (Сергей) | Причина в коде | Тяжесть |
|---|---|---|
| «При нажатии каретка прыгает вверх», директивы слипаются в начале шаблона | Двойной дефект `TemplateEditorPanel.applyEdit`: (а) кнопки без `onMouseDown={e=>e.preventDefault()}` блюрят textarea; (б) restore каретки через `requestAnimationFrame` хрупок (rAF паузится в фоновых окнах, гонки со scroll). Плюс **дизайн-дыра**: если каретки в textarea ещё не было, `selectionStart = 0` → директива вставляется в самое начало документа — ровно твои три слипшиеся `{{!style:}}` наверху | 🔴 фикс обязателен до merge |
| Мало места, левую панель хочется скрывать | Редактор зажат между сайдбаром админки, тулбаром и палитрой «Змінні форми» (палитра уже в `<details>`, но открыта по умолчанию; сайдбар админки не сворачивается) | 🟡 дёшево |
| Превью маленькое и «не отображает действительность» | Правая колонка ~1/3 ширины; A4-страница «Розкладки» ужата в неё с масштабом; режим «Документ» — сплошной поток без страниц. Клик-на-превью → fullscreen нет | 🟡 дёшево (overlay) |
| «Выделил только `{{plaintiff_name}}` → bold — жирным станет вся строка» | Фундамент: весь конвейер стилей **попараграфный**. `styleHints = {индекс_абзаца: [ключи]}`; `apply-typography.js` красит диапазон целого абзаца в Google Docs. Инлайн-диапазонов (аналог «runs» в Word) в модели просто нет | 🔵 это НЕ баг, это граница архитектуры |
| «В идеале применил — сразу видишь как в документе» | Превью живое, но связь «строка DSL ↔ абзац превью» никак не подсвечивается; сырой DSL (`{{#if}}`, `{{!style:}}`) юрист видит как код | 🔵 стратегический вопрос (см. ресёрч) |

## 2. Текущая архитектура: честные плюсы

1. **SSoT и безопасность рендера.** Один plain-text шаблон = то, что рендерит боевой движок (parity 1032 теста). Никакой конвертации WYSIWYG↔DSL — нечему ломаться молча. Для legally-critical документов это главный актив.
2. **Условная логика выразима полностью.** `{{#if}}/{{else if}}/{{#each}}` с произвольными выражениями — то, на чём (по нашему же рыночному ресёрчу) ломаются все WYSIWYG.
3. **Гейт + черновик + ревизии уже работают** (ночная приёмка): юрист не может сломать прод, всё откатывается.
4. **Дёшево в поддержке**: textarea + чистые функции вставки; 406 юнит-тестов уже покрывают ядро.
5. **Превью на реальном движке** — «Документ» и «Розкладка» рендерятся тем же кодом, что и прод (не имитация).

## 3. Честные минусы

1. **Textarea — плохой дом для 15-килобайтного шаблона**: нет подсветки синтаксиса, нет сворачивания блоков, каретка/скролл хрупкие (баг подтверждён), поиска нет.
2. **Юрист видит код.** `{{#if court_fee_exempt == 'yes'}}` — барьер для Ольги; наша цель «юрист без SQL» достигнута наполовину: без SQL, но с DSL.
3. **Стили только попараграфные** — инлайн-жирный (кейс «Позивач: **Иванов**») невозможен без расширения формата styleHints, движка, apply-typography и превью (+ parity-тесты). Это изменение Tier 2 в legally-critical слое.
4. **Нет связи редактор↔превью** (sync-scroll / подсветка абзаца) — «смотреть изменения неудобно» именно поэтому: применил стиль внизу, а где он в превью — ищи глазами.
5. Превью «Документ» не показывает страницы (только «Розкладка»), поэтому ощущается «не как документ».

## 4. Что чинится дёшево (кандидаты в web-сессию, до/сразу после merge)

1. 🔴 **Каретка (3 фикса разом)**: `onMouseDown preventDefault` на кнопках тулбара/палитры + restore через `useLayoutEffect` (pendingCaret-ref) вместо rAF + guard «каретки ещё не было» (кнопки стилей disabled с tooltip «Клацніть у текст шаблону», пока textarea ни разу не фокусилась).
2. 🟡 **Fullscreen-превью**: клик по превью (или кнопка ⤢) → модальный overlay на весь экран с A4-масштабом 100%, Esc/✕ закрыть. Компоненты уже есть (`DocumentPreview`/`DocumentLayoutPreview` принимают ширину).
3. 🟡 **Сворачивание**: сайдбар админки — collapse-кнопка; палитра «Змінні форми» — `<details>` закрыт по умолчанию при узком экране; сплиттер редактор/превью перетаскиваемый.
4. 🟡 **Подсветка «где я»**: на input/selection в textarea вычислять индекс абзаца каретки (split('\n') до selectionStart) → подсвечивать соответствующий абзац в превью и скроллить к нему. Дешёвая версия sync-scroll, закрывает «применил и сразу вижу».
5. 🟢 Локализация ошибок гейта (таблица типовых паттернов в `templateGate.ts`, движок не трогаем) — уже в рецензии критика.

## 5. Инлайн-стили («runs») — оценка отдельно

Минимальный путь, если решим делать:
- Синтаксис DSL: инлайн-теги вида `{{#bold}}…{{/bold}}` (симметрично существующим блокам; parser уже умеет парные теги).
- `styleHints v2`: `{paraIdx: {styles: [...], runs: [{start, end, styles}]}}` — offsets в символах внутри абзаца **после** подстановки переменных (движок знает финальный текст — оффсеты считаются в момент рендера).
- `apply-typography.js`: runs → Google Docs `updateTextStyle` с range внутри абзаца (внимание: индексы Google Docs в UTF-16 code units — кириллица ок, но эмодзи/суррогатные пары надо тестировать).
- Превью: `toParagraphs` → сегменты абзаца со стилями (по образцу уже сделанного `splitAnnotated` для чипов).
- Тулбар: «Жирний» при выделении ВНУТРИ строки → обернуть в инлайн-тег; при выделении строк целиком → как сейчас.
- Цена: движок+типографика+превью+тулбар+parity/юнит-тесты ≈ отдельная сессия конвейера, затрагивает legally-critical слой ⇒ Tier 2 спека-дополнение, НЕ впихивать в Сессию 3.

**Важно**: кейс Сергея («Позивач: **{{plaintiff_name}}**») — реальная типографика судебных документов (ПІБ сторон часто выделяют). Т.е. это не каприз, а функциональный пробел — но решать его лучше после вердикта ресёрча (возможно, вместе с апгрейдом редактора, чтобы не делать дважды).

## 6. Открытый стратегический вопрос (ждёт веб-ресёрч)

Три сценария эволюции (оценит исследователь):
- **S1**: остаёмся на textarea + фиксы из §4 (минимум риска, юрист всё ещё видит DSL);
- **S2**: CodeMirror 6 поверх того же DSL — подсветка, чипы-декорации над `{{поле}}`, иконки вместо `{{!style:}}`, fold условных блоков (полу-WYSIWYG, SSoT не меняется);
- **S3**: полный WYSIWYG (ProseMirror/Lexical) с round-trip в DSL — то, что рынок делает плохо на условной логике; наш прошлый ресёрч это уже отклонял.

Предварительная позиция (моя, до ресёрча): S2 — золотая середина: SSoT-текст остаётся истиной (нулевой риск для рендера), а Ольга перестаёт видеть сырые теги.

## 7. Вердикт веб-ресёрча (детали: `2026-07-03-editor-architecture-research.md`)

Ресёрч подтвердил ставку на **S2: CodeMirror 6 + styleHints v2 (runs) в движке**:

- **Word/OOXML**: перенимаем ровно одно понятие — «run» (`w:r/rPr`, плоский диапазон символьных стилей внутри абзаца). styleHints v2: `{paraIdx: {styles: [...], runs: [{start, end, styles}]}}`, offsets после подстановки переменных (sentinel-токены в движке); Google Docs `updateTextStyle` уже принимает такие диапазоны (применять по убыванию индексов). Изменение движка **аддитивно** — старые шаблоны рендерятся байт-в-байт, parity-тесты остаются зелёными.
- **Рынок**: юристам никто не даёт голую textarea; доминируют Word-add-in (Gavel, Clio Draft, HotDocs, Woodpecker) и дорогие собственные WYSIWYG (Juro, Doczilla). Наш side-by-side паттерн легитимен (это Alt+F9 Word'а) — сырая только левая панель.
- **Фреймворк**: CodeMirror 6 — документ остаётся DSL-строкой (lossless round-trip тривиален по построению), чипы = штатный `MatchDecorator + Decoration.replace`; прод-прецеденты полу-WYSIWYG над разметкой — Obsidian Live Preview, Overleaf Visual Editor. Lexical отпадает (нет чистых декораций), ProseMirror = round-trip-риск тихой порчи шаблонов (проект уже отклонял).
- **Оценки**: S1 2–4 дня (не решает фидбек целиком) · S2 1.5–3 недели инкрементально · S3 4–8+ недель + риск для legally-critical слоя. S1-фиксы (каретка, fullscreen-превью, zoom A4) — первые инкременты ВНУТРИ S2.
- S3 (полный WYSIWYG) отложить до фазы «редактор как внешний продукт Service Builder».
