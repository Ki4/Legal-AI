## Как читать уровни
- ✅ **live** — работает в проде прямо сейчас
- 🟢 **solid** — сделано надёжно (может быть ещё не в проде)
- ⚠️ **partial** — есть, но с дырами / грубо / только частично
- ❌ **gap** — нет, или доступно только разработчику

## Детально по блокам: Сейчас → Цель → Переход

### 1. UX Telegram (Mini App)
- **Сейчас** ✅ live: форма с табами, `show_if`, анимация, preview → оплата(заглушка) → PDF. End-to-end на 2 услугах.
- **Цель:** завершённый UX — понятные состояния загрузки/ошибки/успеха, онбординг, элементы доверия.
- **Переход:** (a) пройти каждый экран, собрать шероховатости → (b) состояния ошибок/пустоты/загрузки → (c) микрокопия и доверие.

### 2. Forms — конструктор формы
- **Сейчас** 🟢 solid: реальный визуальный FormBuilder (добавить/править/клонировать/переставить поля и табы, 8 типов, обязательность, подсказки, `show_if`). Юрист правит форму без кода.
- **Дыра:** `show_if` в UI — только ОДНО условие `==`/`!=`. Составные (`>`, `<`, `all`/`any`) поддержаны в данных, но авторятся только dev-скриптом.
- **Переход:** составной конструктор условий + валидации полей в UI.

### 3. Docs generation — движок документов
- **Сейчас** ✅ live (движок) / ⚠️ качество: диспетчер по `generation_mode`, шаблон читается из БД через общий `render-document.js`; типографика — через Google Docs API → экспорт PDF → Supabase Storage.
- **Дыры:**
  1. ⚠️ **Критичный шов:** новая услуга из админки создаётся с `generation_mode='js'` (дефолт БД) → в проде уходит в запасную ветку и падает (нет js-билдера под её slug). Единственное незакрытое место петли.
  2. Качество вёрстки/текста надо доводить (твой пункт) — часть ждёт легальных формулировок Оли.
  3. Google-инфра для генерации не prod-grade (сервис-аккаунт, квоты, стабильность).
- **Переход:** (a) закрыть шов — новая услуга по умолчанию `template`; (b) убрать дыры `________`, довести вёрстку; (c) prod-грейд генерация (service account + лимиты) либо замена Google Docs на серверный рендер.

### 4. План / roadmap
- **Сейчас** ⚠️: стратегия v2 есть, но приоритеты в сумбуре (roadmap.md + IMPROVEMENTS + issues + память).
- **Цель:** одна живая карта фаз (этот документ) как источник порядка.
- **Переход:** привязать блоки к фазам GTM (см. «Порядок фаз» ниже).
- *Примечание:* если под «план» ты имел в виду **тарифные планы/подписку** — это отдельный блок оплаты, скажи, распишу отдельно.

### 5. Продукт — позиционирование
- **Сейчас** 🟢 solid (в стратегии): «не AI-юрист, а генератор документов с честной эскалацией к живому юристу». Юридически безопасно.
- **Дыра:** нет имени/бренда (открытый вопрос стратегии §9), нет публичной оферты, value prop не на 1 странице.
- **Переход:** имя-кандидаты → value prop 1 страница → оферта («инструмент генерации», не «юр-услуга»).

### 6. Визуализация продукта
- **Сейчас** ❌ gap: «демо» = само приложение; нет лендинга, нет демо-нарратива, нет «проверено юристом X».
- **Цель:** демо-сценарий для Оли сейчас → лендинг + доверие-слой позже.
- **Переход:** (a) клик-тур «от формы до готового документа» → (b) страница-визитка → (c) «verified by» на документе.

### 7. База данных
- **Сейчас** 🟢 solid: Supabase, 31 миграция, RLS, шифрование данных дела, retention, единый `status`.
- **Дыры:** data residency не решён (§9 стратегии), процесс бэкапов/восстановления не описан, dev и prod вероятно на одной базе.
- **Переход:** разделить dev/prod (связано с VPS) → бэкапы → зафиксировать миграционный процесс.

### 8. VPS / инфраструктура
- **Сейчас** ❌ gap: n8n локально в Docker + ngrok-тоннель. Нет постоянного хоста, нет dev/prod.
- **Цель:** Hetzner CX22 (~€5/мес) + Docker + nginx, домены + TLS, dev/prod контуры, ngrok убрать.
- **Переход:** поднять VPS → перенести n8n → домены/TLS → разделить контуры.

### 9. Безопасность
- **Сейчас** ⚠️ partial: шифрование ✅, RLS ✅, rate-limit ✅ (миграция 024).
- **Дыры:** секреты в n8n JSON (issue #24 открыт), проверка подписи Telegram `initData`, GDPR consent/retention UI. **Аудит нашёл:** роут `/design` смонтирован БЕЗ авторизации (публично доступная dev-страница) — быстрый фикс.
- **Переход:** закрыть `/design` → секреты в env/vault → `initData` подпись → consent.

### 10. Админка для юриста
- **Сейчас** 🟢 solid — самая зрелая часть. Через UI: создать услугу, FormBuilder, редактор шаблона (CodeMirror, чипы, стиль-тулбар, история версий, фокус-режим), preview формы и документа, publish, статус, health-панель, заметки/заявки.
- **Дыры (из аудита):**
  - `generation_mode` не выставляется в UI → см. шов в блоке 3 (главная).
  - **Мёртвый чек-лист AI-качества:** 5 чекбоксов без state/onChange — юрист их отметит, а они ничего не делают.
  - Категории захардкожены (2 шт., family/medical) — новую вертикаль добавить = править код.
  - Две пересекающиеся вкладки «как делается документ» (AI-prompt vs шаблон) без пояснения, какая живая — путает.
- **Переход:** убрать/подключить мёртвый чек-лист → пояснить/скрыть неживую вкладку → UI-контрол `generation_mode`.

### 11. Масштабирование
- **Сейчас** ⚠️ фаза 0: 2 услуги (развод, алименты), стратегия фаз есть.
- **Цель:** 5 услуг (цель PoC) → бета 3–5 юристов Оли → полу-авто → билдер.
- **Переход:** закрыть шов генерации → каталог 5 услуг с Олей → потом билдер (фаза 3–4).

### 12. Маркетинг
- **Сейчас** ❌ gap: не начат; в стратегии — инфлюенсеры + «проверено юристом» как доверие-слой.
- **Переход:** после фазы 1 (бета) → первые юристы-лица → реферальная модель.

## Порядок фаз (плавный переход, крупными мазками)

- **Фаза A — сейчас, до/с Олей:** цельная авторская петля + демо. (блоки 1, 3-шов, 6, 10)
- **Фаза B — с Олей:** каталог 5 услуг, легальные формулировки, доверие-слой, качество документов. (блоки 3-качество, 5, 11)
- **Фаза C — prod-готовность:** VPS + dev/prod, оплата + ФОП, prod-хранилище, хардненинг безопасности, бэкапы БД. (блоки 7, 8, 9 + оплата)
- **Фаза D — масштаб:** билдер услуг, маркетинг, инфлюенсеры. (блоки 11, 12)

Твой инстинкт «сначала авторская петля, потом оплата» ложится ровно в A→B→C. Оплата и ФОП живут в фазе C — после того, как петля и каталог доведены. Это не противоречит стратегии v2 (там оплата — P0 для продажи, но не раньше, чем есть что продавать цельно).
