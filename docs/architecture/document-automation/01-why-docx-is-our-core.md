# Автозаполнение договоров — PoC: что сделали и почему

_Краткий технический конспект. Дата: 09.07.2026._

## TL;DR
Юрист готовит шаблон в **обычном Word** с плейсхолдерами (`{{поле}}`), система
собирает данные в **JSON** (форма/бот) и на выходе отдаёт **готовый .docx + PDF +
HTML-превью**. Ядро — Word, движок подстановки — `docxtpl` (Python). Всё локально,
без облака, за доли секунды.

---

## Почему Word — ядро (а не что-то ещё)

| Аргумент | Суть |
|---|---|
| **Юрист не меняет привычки** | Он и так пишет договоры в Word. Просто расставляет `{{переменные}}` — учиться нечему. |
| **Полный контроль вёрстки** | Шрифты, поля, разрывы страниц, неразрывные блоки. Для юрдоков это критично (пример — подпись, см. ниже). |
| **Конфиденциальность** | Данные клиента не уходят в облако — обработка на своей машине/сервере. Для юрфирмы часто обязательное требование. |
| **Скорость и автономность** | Генерация за доли секунды, без сетевых запросов и внешних API. |
| **.docx → PDF тривиально** | Из Word в PDF конвертируется один-в-один. Обратно (Google Docs → точный PDF) — сложнее. |

## Почему НЕ Google Docs (как ядро)
Не «плохо», а **не подходит на роль ядра** для этой задачи:

- Работает через API (`documents.batchUpdate`) — медленнее (сетевые round-trip'ы), нужен OAuth / сервис-аккаунты.
- Данные уходят в облако Google — конфликт с конфиденциальностью юрдоков.
- Хуже с динамикой — вложенные циклы и таблицы делать заметно сложнее.
- Меньше контроля над печатной вёрсткой — гарантировать «подпись не на отдельной странице» тяжелее.
- **НО** плюс — облачная совместная работа и шаринг. Поэтому Google Docs у нас в статусе «бонус/потом», не ядро.

## Какие вообще есть подходы (альтернативы)

| Подход | За | Против |
|---|---|---|
| **`docxtpl` (Python) — выбрали** | Локально, быстро, синтаксис Jinja2, юрист остаётся в Word | Точный PDF требует установленного Word |
| **`docxtemplater` (Node.js)** | То же самое, экосистема JS | У нас стек Python — лишняя зависимость |
| **Google Docs API** | Облако, шаринг из коробки | Медленно, OAuth, данные в облаке, слабее с таблицами |
| **No-code (Make/Zapier + Plumsail/Documint)** | Без кода, быстрый старт | Vendor lock-in, абонплата, данные уходят стороннему сервису |
| **HTML → PDF (WeasyPrint/Puppeteer)** | Полный контроль пагинации через CSS | Придётся переносить все шаблоны в HTML — юрист теряет Word |
| **python-docx «с нуля»** | Генерация кодом без шаблона | Юрист не может править макет — слишком жёстко |

**Вывод:** `docxtpl` + Word — лучший баланс «юрист работает в привычном Word» ×
«данные локально» × «полный контроль вёрстки» для нашего стека (Python).

## Как сейчас работает флоу

```
Юрист → template.docx (с {{переменными}})
Бот/форма → data.json (данные клиента)
        │
        ▼
  fill_contract.py   (docxtpl: подстановка полей,
        │             разворот таблицы этапов, условные блоки)
        ▼
    output.docx  ──►  to_pdf.py      → output.pdf   (через Word, для печати/подписи)
        └─────────►  preview_html.py → .html        (mammoth, быстрый веб-превью)

Всё одной командой: run_pipeline.py
```

Синтаксис в шаблоне:
- `{{ поле }}` — простые поля (номер, дата, стороны, сумма);
- `{%tr for … %} … {%tr endfor %}` — строки таблицы (цикл по этапам);
- `{% if … %} … {% endif %}` — условные блоки (например, аванс).

## Что делает это не «игрушкой», а инженерным решением
Мы не просто подставляем текст — решили **юридически критичный нюанс вёрстки**:
блок подписей не должен разрываться / уезжать на отдельную страницу.

- Обычной защиты (`cantSplit` построчно) **недостаточно** — таблица всё равно может разорваться между строк.
- Добавили цепочку `keep_with_next` → блок держится целиком.
- **Доказали автотестом**: прогон 12–25 этапов; на «слабой» версии при 20 этапах подпись реально рвалась между страницами, после фикса — все конфигурации целы.

## Честные границы PoC (что ещё не сделано)
- PDF требует установленного Word (иначе нужен LibreOffice-fallback).
- Пока нет: валидации обязательных полей JSON, пакетной обработки, реального
  приёма данных от бота/формы (JSON кладём вручную), интеграции с Google Docs.

## Следующие шаги (на выбор)
1. Валидация обязательных полей JSON с понятной ошибкой.
2. Пакетный режим: папка JSON → папка PDF.
3. Демо приёма данных от бота/формы → JSON.
