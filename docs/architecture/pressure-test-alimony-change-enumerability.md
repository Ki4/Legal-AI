# Pressure-test: чи перечислиме «обґрунтування» alimony-change? (де-риск AI-харнесу)

> **Навіщо.** Критика розвороту (DECISIONS «детермінізм-first; харнес відкладено,
> не поховано») поставила guardrail: аудит довів, що AI-харнес (L4-критики, RAG,
> GraphRAG) **не live** — але НЕ що він непотрібен. Перевірити на ПЕРШОМУ
> начебто-неперечислимому документі, перш ніж списувати. Кандидат — єдиний пілот
> харнесу: LLM-абзац `ai.reasoning` в alimony-change. Це та перевірка.

## Що LLM реально генерує (а не що здається)
Джерела: `n8n/prompts/alimony-change-reasoning.txt` + `n8n/templates/services/alimony-change.document.txt:78-96`.

- LLM пише **ЛИШЕ середній абзац** — `{{#if ai.reasoning}}…{{else}}[фікс-блок ст.182]{{/if}}` (рядки 88-92). І там **вже є детермінований fallback** (ст.182), бо hybrid вимкнений.
- **Решта «обґрунтування» ВЖЕ детермінована** в шаблоні: посилання на рішення/договір + дата + сума (78-79), «обставини істотно змінилися» (82-86), рамка ст.192 з гілками increase/decrease + court/agreement (94), ЦПК-нота (96).
- З 4 пунктів структури промпта (§6 — посилання на рішення / перелік фактів / ст.192+182 / висновок) **три (1, 3, 4) шаблон уже робить**. Унікальний внесок LLM = **лише п.2: вплести обрані `changed_facts` у наратив**.

## Чи перечислимий цей внесок? — ТАК
- `changed_facts` = **enum з 8 значень**, кожне вже має вивірену юр-фразу (промпт §3 / `CHANGED_FACTS_LABELS` у `prepare-reasoning.js`).
- Абзац зводиться до: «З моменту [рішення] змінилися такі обставини: [фраза на кожен обраний факт]; згідно зі ст.182 СК це враховується при визначенні розміру». Це **детермінований блок-перелік (ярус B)**, а не відкритий аргумент.
- **Висновок:** LLM-частину можна замінити lawyer-блоками по `changed_fact`. alimony-change здатний стати чистим `template`-сервісом **без L3 (LLM) / L4 (критики) / L2 (RAG)**.

## Чесні застереження (щоб не переоцінити)
1. **Юр-достатність факту — НЕ робота LLM.** Промпт сам каже: `cost_of_living_up` — НЕ підстава за ст.192. Тобто валідність і комбінації фактів має пре-вирішити юрист (enum-правила), а не модель. Темплейт робить це детерміновано й безпечніше.
2. **Гладкість прози.** LLM пише плавніше, але для судового обґрунтування структурований перелік — норма й навіть чіткіше; гладкість не варта LLM-ризику на court-ready тексті.
3. **Хвіст** (незвична 9-та обставина поза enum) — це випадок для **ескалації до живого юриста (D)**, а не для C (LLM). Навіть неперечислимий хвіст → D, не C.

## Вердикт + наслідок
- **alimony-change reasoning = перечислимий (B) + ескалація хвоста (D). C (LLM) не виправданий навіть тут.**
- Отже AI-харнес (критики / RAG / GraphRAG) наразі **не має ЖОДНОГО сервісу, що його потребує**. Він лишається «what-if» під майбутній сервіс із *справді* відкритим аргументом **ТА** достатнім обсягом, щоб не ескалювати кожен кейс.
- **Конкретний анлок:** alimony-change можна вивести з `disabled/hybrid` у **live як pure-`template`** (enum-блоки reasoning по `changed_facts`), без LLM — 3-й живий сервіс детермінованим шляхом. Tier-2 → sign-off Олі на формулювання блоків + per-fact валідність.

## Що це міняє в плані (July)
- Шлях: **«template + enum-блоки в стилі `changed_facts` + ескалація хвоста»**; харнес спить далі.
- **НЕ видаляти** харнес (відкладено-не-поховано лишається в силі), але й **НЕ будувати** під нього, доки не зʼявиться сервіс із доказово-неперечислимим, високооб'ємним аргументом. Поки таких немає — це підтверджено на єдиному кандидаті.
