## 1. Теза

**Новий білдер послуг — це КОМПІЛЯТОР, а не редактор форм.**

Контур: **один `.docx` = єдине джерело правди** (текст документа + `customXml`-блоб з метаданими полів) →
**компілятор** → на виході: рядок у таблиці `services` + JSON-схема MCP-тула + `watched_laws` + чекліст.

Наслідки:
1. **Рядок `services` = ПРОЄКЦІЯ, а не джерело.** Його можна знести і зібрати заново з `.docx`. Звідси
   когерентне гасло **«веб = дзеркало»**: адмінка показує послугу, але не є її джерелом.
2. **Word Add-in = редактор контракту**, компілятор = той, хто цей контракт збирає у робочу послугу.
3. **Per-service скіл — це баг, а не фіча.** Мета — generic-роутер + широкий канал схеми, щоб НЕ писати
   скіл (≈150 рядків прози) під кожну послугу.

**Мірило амбіції (рішення Сергія):** послуга №10 додається **без жодного рядка нашого коду і без жодного
рядка прози у скілі**.

## 2. Справжня діра — не Word, а ШИРИНА КАНАЛУ СХЕМИ

JSON-схема, яку бачить LLM, сьогодні **викидає `tab`** (порядок питань) і перетворює `validation` на прозу.
Саме тому per-service скіл існує — щоб компенсувати втрачене. Порозрядний розбір `alimony-claim/SKILL.md`:

| Що у скілі | Куди має піти замість скіла |
|---|---|
| Порядок табів → дані | у канал схеми (зберегти `tab`/порядок) |
| Межі/відмови послуги | **проза ВІД ЮРИСТА** — юридичне судження, авторська робота, не наш код |
| Формат-лор | `hint` поля |
| Статті законів | з цитат у тексті документа |
| Протокол інтерв'ю | один generic-роутер на всі послуги |

**Ставка всієї витівки = розширити канал схеми.** Доводиться порядковою звіркою ДО написання першого
рядка надстройки.

### 2.1 ✅ Уточнення фактом + РІШЕННЯ «скіл-на-послугу vs generic-роутер» (session 88, 2026-07-18)

> **claim ≠ fact:** теза §2 «схема викидає умови, per-service скіл компенсує» — **перебільшена**. Звірено з
> кодом `apps/mcp-server/src/form-schema.ts`.

Що tool `inputSchema` **вже** несе на КОЖНЕ поле (генериться з `form_config`):
- label + `hint` + `explanation` (`buildDescription`)
- варіанти `value — label` для choice/multicheck
- формат-правила email/phone/ІПН/IBAN/дата/число (`FORMAT_NOTES`)
- **умова показу `show_if` → проза «Питати ЛИШЕ якщо: …»** (`form-schema.ts:60`) — тобто «як питати
  залежно від відповідей» УЖЕ в туле
- `maxLength`, `enum`, `pattern`

Отже реальна **залишкова** діра мала: (1) **порядок питань** (`tab`) не сигналізовано явно — іде неявно
порядком `config.steps`; (2) **протокол інтервʼю + юр-межі/відмови** = судження юриста.

**РІШЕННЯ (курс):**
1. **ОДИН generic-роутер-скіл** — протокол приймання, спільний для всіх послуг (питай по порядку; при
   помилці валідації перепитай; покажи зведення + підтвердь; відмов, якщо поза компетенцією). Багаторазовий.
2. **Розширити схему** явним сигналом порядку питань.
3. **Юр-межі per-service = ДАНІ на послузі** (поле, що впорскується в опис тула), **НЕ** рукописний
   скіл-файл на послугу.

**Наслідок:** «skills = опис послуги» лишається вірним — але опис живе **в туле** (схема + опис +
boundaries-дані), а роль «скіла» зводиться до одного роутера. Per-service скіл-ФАЙЛ
(`alimony-claim/SKILL.md` тощо) прибираємо; його потрібний КОНТЕНТ стає даними. Це і є критерій «послуга
№10 без рядка коду і прози»: `.docx` → компілятор зібрав тул → роутер підхопив.

## 3. Що НЕ прийде з Word ніколи (назвати чесно — інакше «ноль коду» = брехня)

1. **Обчислюваний шар** (склонення ПІБ, дати прописом) — це код рушія, не Word.
2. **Юридичні константи** — прожиткові мінімуми 2026 і дріб ст.183 захардкоджені в
   `render-document.js:548` → щорічний тихий дрейф у суді. Пропозиція: `legal_constants` як дані під
   охороною law-monitor (окремий трек).
3. **Add-in ≠ VBA:** немає події «юрист править», не можна заблокувати збереження → зіпсований шаблон
   ловить **компілятор** (гейти на сервері), а не Word.

**Розвилка A/B (вирішується фактом у спайку):**

- **B (рекомендація)** — Content Control як маркер + jinja впорскує компілятор (jinja у документі юриста
  НЕМА → зламати неможливо).

## 5. Подарунок: watched_laws безкоштовно

Юрист **уже пише** «ст. 180 СК України». У репо є регулярка цитат + `extract-citations.mjs`. Компілятор
збирає `watched_laws` з тексту → **law-monitor (живий, GitHub Actions, s79) охороняє Word-послугу з
народження, БЕЗ SQL-сіду**.

## 7. Де живе код і як мержити фазами

- **Код і верифікація:** гілка `feat/word-to-service-poc` (містить `apps/doc-engine`, `apps/word-addin`,
  `scripts/word-to-service.mjs`). `feat/doc-engine` — предок (повністю всередині word-to-service-poc),
  тримаємо як історію + Tier-2 спека.
- **Наступний крок = СПАЙК** (потрібні руки Сергія — Claude не клікає у Word): sideload надстройки →
  кнопки → **Ctrl+S** → `TORTURE_TPL=<копія> pytest tests/test_torture.py`. Перша перевірка — чи вціліє
  CDATA.
- **Порядок у main (фазами, /feature-spec `word-addin-authoring`, Tier 2):**
  1. **Фаза 1 «Компілятор»** — контракт → канал схеми → generic-роутер → цитати→watched_laws.
     **Доводиться БЕЗ Word взагалі**, офлайн, на `alimony-poc.docx`. Низький ризик → мерж у main першою.
  2. **Фаза 2 «Надстройка»** — Word Add-in.
  3. **Фаза 3 «Публікація»** — ендпоінт **insert-only, 409 на існуючий slug** (єдине, що стоїть між Word
     і живим каталогом).
