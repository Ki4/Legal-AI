## 0. Контекст і чому косметика тут — не примха

**Хто користувач.** Адмінку відкриває **Olga — юрист, нетехнічна людина**, Human-in-the-Loop рев'юер. Вона додає послуги, переглядає, як форма зіставляється з документом, лишає коментарі, підтверджує зміни законів. Другий користувач — **Sergey (owner/розробник)**, читає інбокси заявок.

**Емоційна задача.** Юрист працює з документами, де ціна помилки — суд. Довіра до інструмента будується через **спокій, охайність, передбачуваність** — те саме, що цінується в добре зверстаному юридичному документі. Поточна панель виглядає як **dev-дашборд** (темний slate, емодзі, дрібний щільний текст, технічний жаргон). Це не «погано» — це просто розмова інженера з інженером, а має бути розмова продукту з юристом.

**Орієнтир — Claude Desktop.** Не «темна неонова панель», а: світле тепло-нейтральне тло, багато повітря, один стриманий акцент, справжня типографіка замість мішанини розмірів, іконки замість емодзі, мінімум одночасних елементів на екрані. Мінімалізм тут = **прибрати візуальний шум, лишити сенс**.

## 1. Що є зараз — інвентар (7 екранів + спільні елементи)

Адмінка живе в `apps/client/src/admin/`, окрема збірка (`admin.html` → `dist-admin/`, `npm run dev:admin` :5174), спільний `src/` з клієнтським TWA. React + React Router + Tailwind (без UI-бібліотеки) + Supabase.

| # | Маршрут | Файл | Призначення |
|---|---------|------|-------------|
| 1 | `/login` (+ forgot/reset) | `pages/LoginPage.tsx` | Вхід юриста (email+пароль, Supabase Auth) |
| 2 | `/services` | `pages/DashboardPage.tsx` | «Мої послуги» — сітка карток послуг, головний екран |
| 3 | `/services/:id` | `pages/ServiceViewPage.tsx` | Read-only «дзеркало» послуги: health, анатомія документа, закони, форма як є, коментарі |
| 4 | `/services/:id/edit` | `pages/ServiceEditPage.tsx` | Редактор: 3 таби (конструктор форми / AI-промпт / налаштування) + live-превью |
| 5 | `/notes` | `pages/NotesInboxPage.tsx` | «Коментарі» — інбокс фідбеку юриста по всіх послугах |
| 6 | `/requests` | `pages/ServiceRequestsPage.tsx` | «Заявки» — замовити нову послугу + завантажити приклад документа |
| 7 | `/law-changes` | `pages/LawChangeLogPage.tsx` | «Зміни законів» — черга на ревʼю змін у відстежуваних законах |

**Спільний каркас** — `components/AdminLayout.tsx`: ліва сайдбар-навігація (4 пункти: ⚖️ Мої послуги / 💬 Коментарі / 📝 Заявки / 📋 Зміни законів), лого «🏛 Legal AI / Admin Panel», email + «🚪 Вийти» внизу. На мобільному — бургер + top-bar + висувна шторка.

### Поекранно

**2. Dashboard «Мої послуги».** Заголовок + кнопка «+ Нова послуга». Над сіткою — 1-2 банери метрик (`Abstention rate: N%`, `Документи з неповним чеклістом: N%`) за 30 днів. Сітка карток (1/2/3 колонки). Картка: іконка-емодзі + назва + опис, рядок метаданих (health-крапка 🟢/🟡/🔴, `📋 N полів`, `🗂 N табів`, `💰 ціна`), статус-бейдж + кнопки lifecycle (активувати/деактивувати) + дії 👁/✏️/🗑. Скелетони при завантаженні, empty-state з великим ⚖️.

**3. ServiceView «дзеркало».** Top-bar (← Назад, 👁 Форма клієнта, ✏️ Редагувати). Картка-шапка: іконка, назва, статус-бейдж, `🧩 режим`, лічильники, `/slug`. Блок **health-світлофора** з причинами списком. Секція **🔬 Анатомія документа** — 3 колонки діфа (Використовуються / Не в шаблоні / Бракує у формі) з чипами-полями. Секція **🔗 Закони** — статті зі ст.N-чипами + бейдж «застаріло». Секція **📋 Форма як є** — поля по табах, кожне поле з типом, `*`, опціями, умовою `⚡ show_if`, розкривними «технічними деталями». Внизу — панель коментарів юриста.

**4. ServiceEdit «редактор».** Top-bar (← Назад, назва, dirty-крапка ●, 👁 превью, статус-`<select>`, 💾 Зберегти). Під ним — таб-бар (📋 Конструктор / 🤖 AI-промпт / ⚙️ Налаштування). Зліва контент таба, справа (тільки xl) — **live-превью реальної клієнтської форми на білому тлі**. AI-таб: блок порад + чипи-змінні `{{answers}}` + `<textarea>` промпта + ручний «чеклист якості» (нефункціональні чекбокси). Settings: іконка, ціна, опис, підзаголовок, превʼю URL.

**5/6/7. Три інбокси.** Майже однаковий патерн: заголовок + чекбокс-фільтр «Лише відкриті/очікують (N)», список карток, кнопка-тогл `✓ Вирішено` / `↩ Відкрити`, empty-state з великим емодзі. Requests додатково має composer (назва/опис/закони/файл). Law-changes — статус-бейджі дій + поле нотатки + кнопки ревʼю.

## 2. Дизайн-система «як є» — що використовується і чому

### Токени (фактичні)
- **Палітра — темна slate:** `slate-950` тло → `slate-900` картки/сайдбар → `slate-800` інпути/вторинне → `slate-700` бордери/hover. Текст: `white` заголовки → `slate-400` вторинний → `slate-500/600` приглушений.
- **Акцент:** `blue-600` (#2563EB), hover `blue-500`, текст-лінки `blue-400`.
- **Семантика статусів:** `emerald-400` (готово/ок), `amber-400` (увага), `red-400` (проблема), подекуди `yellow-500` (умови).
- **Радіуси:** `rounded-xl` (12px) інпути/кнопки, `rounded-2xl` (16px) картки, `rounded-lg` (8px) дрібні чипи.
- **Шрифт:** system stack (`-apple-system, SF Pro Display, Segoe UI`). Розміри — від `text-2xl` заголовків до `text-[10px]`/`text-[11px]` метаданих.
- **Іконки:** **емодзі всюди** (⚖️ 💬 📝 📋 🔬 🔗 🧩 👁 ✏️ 🗑 💾 🚪 🏛 …).

### Чому так вийшло (чесно)
- **Tailwind utility-first, без UI-кітa** — швидко будувати, але кожен екран верстався окремо → дрейф розмірів/відступів.
- **Темна тема** — типовий дефолт «адмінки/дев-тула», виглядає «технологічно», легко на око розробнику, що її будував.
- **Емодзі як іконки** — нуль залежностей, миттєво, виразно. Але рендеряться по-різному в різних ОС, мають власний колір/вагу, у юридичному контексті читаються несерйозно.
- **Дрібний щільний текст** — прагнення вмістити максимум даних (це ж «дашборд»).

### Патерни, що вже працюють добре (зберегти!)
- **Health-світлофор** 🟢/🟡/🔴 — сильна, зрозуміла ментальна модель «стан послуги».
- **Інбокс-патерн** (фільтр «лише відкриті (N)» + тогл вирішення) — правильний для рев'ю-черг.
- **Lifecycle-статуси** послуги (disabled→active як kill-switch) — чітко.
- **Live-превью форми** в редакторі — юрист бачить очима клієнта. Дуже цінно.
- **Скелетони + empty-states** — є на кожному екрані, це вже зрілість.

## 3. UX-розрив — де болить юристу (матеріал для критики)

### 🔴 Головне протиріччя: dev-тема для нетехнічного юриста
Темний slate + неон-blue читається як «інженерна консоль». Юрист асоціює довіру зі **світлим, чистим, паперо-подібним**. Це не питання смаку — це питання, чи почувається Olga «своєю» в інструменті.

### 🔴 Split-brain: адмінка темна, форма клієнта світла
Клієнтський TWA — це тема **Legal Light** (`surface #F8FAFC`, білі картки, `primary #2563EB`, м'які тіні `shadow-card`, радіус 14px — див. `tailwind.config.js`). Превʼю форми в редакторі — біле на тлі темної панелі. Юрист буквально перемикається між двома візуальними всесвітами в одному продукті. **Уніфікація навколо світлої теми вбʼє це протиріччя і дасть консистентність безкоштовно.**

### 🟡 Емодзі замість іконок
Різна вага/колір/рендер по ОС, «несерйозність». Заміна на один стриманий icon-set (напр. Lucide, 1.5px stroke, монохром) — найбільший «косметичний» виграш за найменших зусиль.

### 🟡 Типографіка-мішанина
`text-2xl` … `text-[10px]` без системи. Дрібний текст (`text-[11px]` метадані, `text-xs` описи) — важко нетехнічному/старшому користувачу. Треба **типошкалу** (3-4 розміри) і збільшити базовий кегль.

### 🟡 Кольорова недисциплінованість
Одночасно blue + emerald + amber + red + yellow + slate + кольори емодзі. Claude-мінімалізм = **один нейтральний фон, один акцент, семантичні кольори лише для статусу**.

### 🟡 Технічний жаргон у тексті для юриста
`Abstention rate`, `checklist`, `🧩 режим: hybrid`, `/slug`, `id: field_x`, мішанина UA/RU/EN. Юрист має бачити **просту українську мову своєї предметної області**, а технічне — ховати під «технічні деталі».

### 🟢 Дрібний борг (вже зафіксований)
- **`✓ Вирішено` читається як статус-бейдж, а не дія** (session 42 UX-борг) — у 3 інбоксах. Зробити очевидно «кнопкою-дією».
- **3 майже однакові інбокси** (notes/requests/law-changes) зверстані трохи по-різному → винести в один компонент-патерн.
- **«Чеклист якості»** в AI-табі — нефункціональні чекбокси (нічого не зберігають). Або зробити робочими, або прибрати.
- **Login** — `🏛` + «v1.0» — перше враження, можна підняти.

## 4. Напрям дизайну — рекомендація для сесії

**Центральне рішення сесії (за Сергієм):** перевести адмінку на **світлу, спокійну, тепло-нейтральну тему** в дусі Claude Desktop, консистентну з клієнтською формою. Нижче — стартова палітра-гіпотеза (фінал — у сесії):

```
Тло (canvas)      #FAF9F5 — тепло-нейтральний папір (а не холодний #FFFFFF)
Поверхня (card)   #FFFFFF з м'якою тінню shadow-card, бордер #ECEAE3
Бордер/розділювач #E8E6DF
Текст основний    #1F1E1B (майже чорний, теплий)
Текст вторинний   #6B6862
Текст приглушений #9B978E
Акцент            #2563EB (лишити — він уже бренд-колір клієнта)
Статуси           зелений / янтарний / червоний — приглушені, не неонові
Радіус            12–14px (як у клієнта: card 14px, btn 12px)
Іконки            Lucide, monochrome, 1.5px stroke, розмір 18–20
```

**Принципи:**
1. **Один акцент.** Blue — лише для головних дій і навігаційного active-стану. Решта — нейтрали + семантика статусу.
2. **Повітря замість щільності.** Менше елементів на екран, більші відступи, крупніший базовий текст (база 14→15/16px, метадані не дрібніше 12px).
3. **Справжні іконки.** Повна заміна емодзі на Lucide. Виняток — health-крапка (це не іконка, а кольоровий індикатор).
4. **Типошкала.** Напр.: H1 24/600, H2 18/600, секція-заголовок 13/600 uppercase, body 15/400, meta 12/400. Зафіксувати й застосувати скрізь.
5. **Ховати технічне.** Жаргон і `id`/`slug`/`режим` — під розкривні «технічні деталі»; нагору — людська мова.
6. **Консистентний інбокс.** Один компонент картки-черги для notes/requests/law-changes.

**Що НЕ чіпати:** health-світлофор, lifecycle-статуси, live-превью, скелетони, інбокс-патерн (логіку), структуру навігації. Це працює — переодягаємо, не переписуємо.

## 5. Що «доробити» (пріоритети)

> Сергій згадав, що генеративних/недороблених екранів мало, але є — їх треба довести до ладу. Нижче — від найбільшого ефекту до точкового.

1. **Токени + тема (фундамент).** Винести дизайн-токени (кольори/радіуси/тіні/тіпошкала) в одне місце, перевести на світлу тему. Один цей крок змінює відчуття всієї панелі. Зачіпає всі екрани автоматично.
2. **Іконки.** Lucide замість емодзі — наскрізно.
3. **Типографіка + відступи.** Застосувати шкалу, прибрати `text-[10px]/[11px]`.
4. **Поекранна доводка (за пріоритетом дотику юриста):**
   - **Dashboard** (головний екран, перше враження) — картка послуги, банери метрик «олюднити».
   - **ServiceView** (де юрист найбільше думає) — секції, анатомія, мова.
   - **3 інбокси** — уніфікувати + полагодити `✓ Вирішено`.
   - **ServiceEdit** — найщільніший, прибрати «чеклист-пустушку», причесати таби.
   - **Login** — перше враження за межами роботи.

## 6. Рішення/питання, які варто закрити в сесії

1. **Світла vs темна** — рекомендація: світла (консистентність із клієнтом + довіра юриста). Підтвердити.
2. **Icon-set** — Lucide (легкий, монохром, React-friendly)? Чи є бренд-обмеження?
3. **Глибина рефактора** — лише токени+іконки (швидко, 80% ефекту) чи повна поекранна доводка зараз?
4. **«Генеративні» екрани** — уточнити, що саме недороблене: AI-промпт-таб? Майбутній білдер послуг? Щоб закласти дизайн наперед.
5. **Бренд** — чи лишаємо `blue #2563EB` як акцент, чи юрфірма має власний колір?
