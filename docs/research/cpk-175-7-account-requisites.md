## 1. Що змінилось у законі

**Норма:** ст.175 ЦПК України доповнено **частиною 7** — Закон № 4833-IX від 07.04.2026
(редакція ЦПК на rada зсунулась `2025-07-17 → 2026-04-24`). Знайдено **реальним diff'ом**
law-monitor (session 50), не вгадано.

**Суть (з верифікованого diff #87):** якщо позов **про стягнення грошових коштів**, позовна
заява повинна містити **реквізити рахунку позивача**, на який підлягають зарахуванню кошти у
разі задоволення позову (рахунок у банку / небанківському надавачі платіжних послуг). Для
**фізичної особи / ФОП** допускається альтернатива: реквізити рахунку **АБО інформація про його
відсутність** + бажаний спосіб отримання коштів.

> ⚠️ Дослівну статутну формулу для самого шаблону має затвердити Оля — нижче чернетки.
> Спроба витягнути verbatim через WebFetch не вдалась (ЦПК завеликий, сторінка обрізається);
> авторитетне джерело суті — наш власний верифікований diff + текст rada
> `https://zakon.rada.gov.ua/laws/show/1618-15` (ст.175, редакція від 24.04.2026).

### 🪤 Пастка термінології (критично не сплутати)
У наших шаблонах **вже є** посилання «**п.7 ч.3** ст.175» (пункт 7 частини 3 — про забезпечення
доказів). Нова вимога — це **ч.7** ст.175 (нова, окрема **частина** статті, про реквізити
рахунку). Це РІЗНІ норми. У новому блоці треба писати «**частина сьома статті 175**», а не
«п.7 ч.3».

## 2. Кого зачіпає у нас

| Послуга | Чи стягнення грошей | Дія |
|---|---|---|
| **alimony** | ✅ завжди (аліменти = стягнення коштів) | додати поле + блок **безумовно** |
| **divorce** з `alimony_claim=true` | ✅ коли є аліментна вимога | додати поле + блок **під `{{#if alimony_claim}}`** |
| divorce без аліментів | ❌ (розірвання шлюбу — не грошова вимога) | не чіпати |
| alimony-change | ⚠️ теж стягнення (зміна розміру) — disabled, перевірити при флипі | відкласти до активації |

**Citations:** ст.175 ЦПК **вже цитується** в обох шаблонах → golden-цитатники НЕ дрейфують
(змінилась лише редакція норми, не її номер). Перевірено: `divorce.citations.json` /
`alimony.citations.json` містять ст.175 ЦПК.

## 3. Точні місця в коді

### alimony
- **Шаблон** `n8n/templates/services/alimony.document.txt` — блок ст.175 ч.3 (рядки **112–120**),
  одразу перед абзацом про судовий збір (р.122). Новий блок ч.7 → **сюди** (той самий стиль
  «повідомляю»).
- **Форма** `scripts/upload-alimony-config.mjs` — таб `plaintiff` (інлайн `formConfig`). Поле(я)
  додати після контактів позивача (`plaintiff_official_email`).

### divorce
- **Шаблон** `n8n/templates/services/divorce.document.txt` — блок ст.175 ч.3 (рядки **144–168**).
  Новий блок ч.7 → теж сюди, **під `{{#if alimony_claim}}`** (бо лише аліментна гілка = стягнення
  коштів). Аліментна вимога в «ПРОШУ» — р.210–211.
- **Форма** `apps/client/src/data/divorceFormConfig.ts` — поле(я) під `show_if alimony_claim == true`.

### Спільне
- **Валідатор IBAN** — у `apps/client/src/lib/validators.ts` зараз НЕ існує (є email/phone/ІПН/
  паспорт). Додати `validateIban` (UA IBAN: `UA` + 27 символів, контрольна mod-97) — опційно, але
  бажано (court-ready якість).
- **doc-engine** змін не потребує — нове поле це звичайний `{{placeholder}}` + `{{#if}}`.

## 4. Пропонований фікс (чернетка — на затвердження Олі)

### 4.1 Поля форми (обидві послуги; для divorce — `show_if alimony_claim == true`)
```jsonc
{ id: 'plaintiff_has_account', type: 'boolean', label: 'Маю рахунок для зарахування коштів',
  required: false, tooltip: 'IBAN у банку або небанківському надавачі платіжних послуг' }
{ id: 'plaintiff_account_iban', type: 'text', label: 'IBAN рахунку',
  placeholder: 'UA00 0000 0000 0000 0000 0000 0000', required: false,
  show_if: { field: 'plaintiff_has_account', operator: '==', value: true } }
{ id: 'plaintiff_account_bank', type: 'text', label: 'Банк / надавач платіжних послуг',
  placeholder: 'АТ КБ «ПриватБанк»', required: false,
  show_if: { field: 'plaintiff_has_account', operator: '==', value: true } }
{ id: 'plaintiff_payout_method', type: 'text', label: 'Бажаний спосіб отримання коштів',
  placeholder: 'поштовий переказ за адресою реєстрації', required: false,
  show_if: { field: 'plaintiff_has_account', operator: '!=', value: true } }
```

### 4.2 Блок шаблону (стиль наявних «повідомляю»)
```handlebars
{{#if plaintiff_has_account and plaintiff_account_iban}}
Відповідно до частини сьомої статті 175 ЦПК України повідомляю реквізити рахунку для
зарахування присуджених коштів у разі задоволення позову: {{plaintiff_account_iban}}{{#if plaintiff_account_bank}}, відкритий у {{plaintiff_account_bank}}{{/if}}.
{{else}}
Відповідно до частини сьомої статті 175 ЦПК України повідомляю, що рахунок у банку або
небанківському надавачі платіжних послуг відсутній; бажаний спосіб отримання присуджених
коштів у разі задоволення позову — {{plaintiff_payout_method}}.
{{/if}}
```
(для divorce — усе обгорнути додатково `{{#if alimony_claim}} … {{/if}}`.)

### 4.3 Що ще оновити
- **Parity-goldens:** alimony (263 байт-у-байт) + divorce — додати нові поля в golden
  `BASE_ANSWERS` і перегенерувати очікувані виходи (інакше parity червоніє). Це головний обсяг.
- **sampleAnswers.ts** (адмінка, превʼю) — додати приклади полів.
- **Деплой:** `node scripts/upload-document-template.mjs alimony` + `… divorce` (шаблони в Supabase),
  оновити form_config alimony (`upload-alimony-config.mjs`) і divorce (Vercel-білд тягне `divorceFormConfig.ts`).
- **Валідатор IBAN** + інлайн-помилка (як #81).

## 5. Питання Олі (для sign-off 1 липня)
1. **IBAN обовʼязковий** чи лишаємо опцію «рахунку немає» (закон дозволяє обидва для фізособи)?
   Якщо обовʼязковий — поле `required: true`, гілку «немає» прибрати.
2. **Точне формулювання** блоку (моя чернетка вище — чи годиться юридично?).
3. Чи треба **назва банку/МФО** окремо, чи достатньо IBAN?
4. «Бажаний спосіб отримання» — **вільний текст** чи фіксований список (готівка в касі суду /
   поштовий переказ / інше)?
5. Чи додавати блок у **divorce** теж зараз, чи лише alimony на демо (divorce+alimony — рідша гілка)?

## 6. Оцінка / рекомендація
- **Тип:** Tier 1-2. Чистий додаток (нове поле + умовний блок), нуль зміни логіки doc-engine.
- **Обсяг:** форма ×2 + шаблон ×2 + parity-goldens (головна частина) + валідатор + деплой.
- **Ризик:** 🟡 юр-коректність; **не блокує демо** (документ генерується, це формальна повнота).
- **Рекомендація:** реалізувати ОДНУ послугу (alimony) повністю як зразок → показати Олі живий
  результат → за її формулюванням докотити divorce. Кодити можна на гілці вже зараз із
  плейсхолдер-формулюванням, фінальний текст — після sign-off (малий радіус, як #67).
