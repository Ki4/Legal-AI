# Бизнес-кейс: платформа комплаенса для медицинских ФОП

**Дата:** 2026-07-14 · **Тип:** консолидированный бизнес-документ (модель · спрос · скоуп · аргументы · гейты)
**Доказательная база:** `docs/research/business-model-research-2026-07.md`,
`docs/research/competitive-analysis-med-fop-2026-07.md` (24/25 фактов верифицированы).

---

## 1. Суть бизнеса

**Продаётся состояние «я в порядке перед регулятором», а не документ.** Документ копируется между
клиентами и обесценивается — состояние скопировать нельзя.

| Уровень | Что | Цена |
|---|---|---|
| **Бесплатно** | Самоаудит по официальному чек-листу проверяющих → «готовность 62%, 3 критичных пробела» | 0 |
| **Подписка** | Закрытие пробелов документами + регуляторный календарь с алертами + доступ к юристу на эскалации | 1.5–2.5 тыс. грн/мес |
| **Апсейлы** | Лицензия «под ключ» (воронка, не бизнес), сопровождение НСЗУ, сопровождение проверки | 4–8 тыс. разово |

## 2. Сегмент

**Соло-медФОП:** лікар-ФОП з чинною ліцензією на медпрактику, практикует сам, 0–3 наёмных.
Приоритет — стоматологи, косметологи с медлицензией, узкие специалисты с кабинетом (больше документов
на пациента → выше риск). Рынок ~35 тыс. лицензиатов.

**Почему этот сегмент:** конкурентов нет (верифицировано); ролей нет — один человек = все роли, продукт
проще на порядок; короткий цикл продажи — боль и решение у одного человека.

**Кто не является клиентом:** клиники/ТОВ (поле существующих юрфирм, нужны роли и долгий цикл),
наёмные врачи (боль не у них), КНП.

## 3. Спрос: что доказано и что нет

| | Статус | Доказательство |
|---|---|---|
| **Транзакционный спрос** — «оформи пакет документов / лицензию» разово за 6–8 тыс. | ✅ **доказан** | Рынок юрфирм живёт на этом; у лидера ниши 1 022 полученных лицензии |
| **Подписочный спрос** — платить ежемесячно за поддержание состояния | ❌ **не доказан** | Попытки подписки на документы у конкурентов откатывались к разовым продажам |

**Разрыв между ними — суть бизнеса.** Пакет документов — это **снимок**; комплаенс — **процесс**.
Клиент, купивший пакет, закрыл одну точку во времени и остался с продолжающимися обязательствами.

**Мост через разрыв:** самоаудит показывает, что «оформил пакет» ≠ «я в порядке» — есть ещё N открытых
пробелов, и они возникают постоянно (регуляторный ритм в §5).

**Следствие для входа на рынок:** не искать новую аудиторию, а **конвертировать существующий поток
транзакционных клиентов в подписку**. Точка входа — юрист, у которого этот поток уже есть: спрос у него
доказан, требуется способ монетизировать его лучше.

## 4. Модель дохода

| Поток | Механика |
|---|---|
| Подписка клиента | 1.5–2.5 тыс. грн/мес; юристу ~70–75%, платформе 25–30% |
| Разовые услуги | комиссия/наценка (лицензия, сопровождение НСЗУ) |
| Фаза 5 | платформа другим юристам: SaaS + rev-share (white-label) |

**Ключевая метрика юнит-экономики — не цена, а часы юриста на клиента в месяц.** Если она не падает
с ростом базы, модель не работает. Проверяется на первых 10 клиентах, а не на 500.

**Ценовые якоря (верифицированы):** штраф за неоформленного сотрудника 86 470 грн = 3–4 года подписки;
недопуск инспектора 138 352 грн; учреждения платят 3.3–9 тыс./мес за инфо-системы; врачи уже платят
~300 грн/мес бухгалтерии. Готовность платить абонплату у сегмента есть — вопрос ценности, не факта.

## 5. Почему подписка имеет основание: регуляторный ритм

Верифицированный календарь обязательств медФОП:

| Горизонт | События |
|---|---|
| Ежедневно | е-медзаписи в ЕСОЗ, фискальные чеки |
| Ежемесячно | отчётность в НСЗУ **до 5 числа** (просрочка → остановка оплат → расторжение договора) |
| Ежеквартально | объединённая отчётность (изменение с 01.01.2026) |
| Ежегодно | контрактование с НСЗУ, медстатформы №20/17, заявка на медосмотры |
| По триггеру | **1 месяц** на уведомление об изменениях лицензии; **7 дней** — уведомление ТЦК; оформление сотрудника **до** начала работы |

Нормативка движется: новые лицензионные условия с 08.01.2026, разовый дедлайн для всех лицензиатов
08.07.2026, полные РРО-штрафы с 08.2025, новый порядок медосмотров, на подходе закон о персональных данных.

## 6. Механизм масштабирования

**Услуга = данные, а не код:**
```
услуга = form_config + document_template + generation_mode + checklist + watched_laws + skill
```
Движок рендеринга service-agnostic — собирает документ, ничего не зная о конкретной услуге.

**Две оси автоматизации читают одну строку `services`:**

| Ось | Что снимает |
|---|---|
| **doc-engine** | *производство* документа — детерминированно, себестоимость ≈ 0 |
| **MCP + skills** | *интервью* — самый дорогой час юриста (tool авто-генерится из `form_config`, skill = сценарий опроса) |

**Тест зрелости движка:** новая ниша закрывается конфигурацией. Требуется код — это баг платформы.

**Следствие для MVP:** самоаудит — это тоже `form_config` (84 вопроса + ветвление = `tabs` + `show_if`),
отчёт — это `document_template`. Значит MVP = конфигурация + тонкий слой скоринга, а не новая система.

**Порядок расширения:** медицина → ветеринария (копия плейбука) → охрана / перевозчики → горизонтальные
пакеты (кадры, ПДн) → другие юристы (white-label).

## 7. Что делаем в MVP

| # | Что | Тип работы |
|---|---|---|
| 1 | Аудит как услуга: `form_config` на 84 вопроса + ветвление по типу практики | конфигурация |
| 2 | **Слой скоринга**: «ответ → пробел → вес/критичность» → % готовности + список пробелов | **новый код (единственный)** |
| 3 | Маппинг «пробел → услуга»: какой документ закрывает какой пробел | данные |
| 4 | Отчёт аудита как `document_template` → PDF | конфигурация |
| 5 | Бот-опросник + доставка в Telegram | доработка |
| 6 | Генерация закрывающих документов | есть |
| 7 | Инструменты юриста: редактор шаблона + preflight + kill-switch | есть ~80% |
| 8 | Эскалация: структурированный вопрос юристу | новое, малое |
| 9 | Оплата | **вручную** (счёт/перевод) |

## 8. Что НЕ делаем в MVP

Роли · мультитенантность · полный личный кабинет · автоматический law-monitor · OCR · RAG/GraphRAG ·
биллинг · аналитика · финансовый модуль · интеграции ЕСОЗ/МІС · база НПА · приложение вне Telegram.

**Правило скоупа:** что можно сделать руками — делается руками. Автоматизируется **только то, что уже
повторилось**. Новая функция = ответ на повторившуюся задачу, а не «на всякий случай».

## 9. Граница компетенции

| Допустимо (констатация факта) | Недопустимо без юриста (юридическая помощь) |
|---|---|
| Самоаудит по официальному чек-листу: «є наказ? так/ні» | Шаблоны документов |
| Календарь опубликованных дедлайнов | Советы «что вам делать» |
| Информирование об опубликованных изменениях | Консультации, эскалация |

**Формулировка:** «вот чего у вас нет по официальному чек-листу» — можно. «Вот что вам нужно сделать,
вот шаблон» — нельзя. Прецедент: регулятор США запретил сервису AI-генерации юрдокументов
рекламироваться как замена юриста — сервис не тестировал качество и не привлёк ни одного лицензированного
юриста. Human-in-the-loop — не ограничение, а условие существования продукта.

## 10. Роль юриста в системе

Юрист — **соавтор услуги**, а не пользователь ПО. Его работа сведена к пяти операциям:

| Задача | Инструмент |
|---|---|
| Утвердить вопросы аудита | документ на согласование |
| Автор/ревью шаблонов | редактор шаблона + предпросмотр + preflight |
| Подпись под услугой (`disabled → active`) | kill-switch |
| Отвечать на эскалации | структурированный вопрос + AI-черновик |
| Видеть заработок | реестр «клиенты × месяц × доля» |

**Конструкция защищает его ёмкость:** формат вопросов ограничен пробелом из аудита (не свободный чат);
повторившийся вопрос становится FAQ и до юриста больше не доходит; сложное — платная эскалация;
он трогает только шаблоны, остальное — зона платформы.

## 11. UX-принципы

**Клиент:** ноль регистрации (Telegram) · ценность до оплаты (аудит бесплатен, пустого экрана нет) ·
никогда не показывать форму на 84 поля — агент спрашивает по одному, как разговор · мгновенная
генерация · одна цифра готовности вместо меню модулей · десктоп-веб для работы с большими документами.

**Юрист:** правит текст, а не заполняет систему · preflight-светофор не даёт опубликовать шаблон с
дырами (репутация защищена машиной) · один вход для эскалаций · финальную кнопку «active» жмёт он.

## 12. Аргументы ЗА

1. **Ниша пустая — верифицировано.** Соло-медФОП за 1.5–2.5 тыс. не обслуживает никто: юрфирмы от
   5–10 тыс. (ручная себестоимость), tech-продукты либо без медправа (54–295 грн), либо для учреждений
   (3.3–9 тыс.). Между ними пусто.
2. **Преимущество структурное, а не ценовое.** Конкурент не спустится к нам, не разрушив свою экономику
   (low-end disruption, а не демпинг).
3. **Движок построен.** Маржинальная стоимость попытки — недели.
4. **Регуляторный ритм реален** (§5) — обязательства на всех горизонтах, с короткими триггерными сроками.
5. **Цена ошибки асимметрична взносу:** один штраф = 3–4 года подписки.
6. **Рынок приучен платить подписку** (бухгалтерия, инфо-системы, AI-юристы).
7. **Нормативка движется прямо сейчас** — свежее топливо для алертов и повод для входа.
8. **Human-in-the-loop = щит.** Отраслевой прецедент доказал нежизнеспособность «AI без юриста».
9. **Опциональность.** Провал медицины не убивает актив: движок закрывает ветеринарию, охрану, перевозчиков.
10. **Ограниченный минус.** Провал даёт валидированный движок, паттерн самоаудита и карту рынка.

## 13. Аргументы ПРОТИВ

1. **Подписочный спрос не подтверждён.** Транзакционный доказан, подписочный — нет (§3). Главный
   неснятый риск.
2. **Зависимость от юриста экзистенциальна.** Он — подпись под шаблонами, эскалация, лицо, доверие
   и платёжный рельс одновременно. Один человек = single point of failure.
3. **Дистрибуции нет.** Бренда нет, канала нет. У лидера ниши 1 022 кейса и репутация. Доверие в
   юруслугах — личное и локальное.
4. **Приём платежей** от украинских ФОП требует юрлица/эквайринга в юрисдикции — практически решается
   через юриста как фронт, что усиливает п.2.
5. **Низкий ARPU требует объёма.** 2 тыс. × 25–30% = 500–750 грн с клиента → нужны сотни клиентов →
   нужен канал и бюджет.
6. **Ёмкость юриста может захлебнуться.** В медправе нет «простых» вопросов; при свободном формате
   один юрист сядет на первой сотне активных.
7. **Ловушка build-first.** Без сигнала спроса легко построить не то и уйти в набор модулей.
8. **Ответственность.** Пропуск изменения → санкции у клиента → претензия к сервису. Нужна оферта
   с разделением ответственности.
9. **Конкурент может опуститься.** У ближайшего игрока уже есть тариф 5 000 и прозрачные пакеты.

## 14. Нейтрализация рисков

| Риск | Ответ | Снят? |
|---|---|---|
| Подписочный спрос не подтверждён | Самоаудит = измерительный прибор: дошли до конца → спросили «как закрыть» → заплатили | частично — фактами, не заранее |
| Зависимость от юриста | Слой диагностики не требует юриста и служит аргументом для его привлечения (приходим со спросом, а не с идеей) | частично |
| Дистрибуции нет | Вход через существующий транзакционный поток юриста (§3), а не через холодную аудиторию | частично |
| Приём платежей | Юрист как фронт; на MVP — ручной счёт | да, ценой усиления п.2 |
| Низкий ARPU | На MVP нужны 5 платящих как сигнал, не сотни | да, для MVP |
| Ёмкость юриста | Формат вопросов + AI-черновик + FAQ + платная эскалация; метрика «часы на клиента» с 1-го клиента | да, конструкцией |
| Build-first | Первым отгружается измерительный прибор; функция = ответ на повторившуюся задачу | да, дисциплиной |
| Ответственность | Оферта: инструмент содействия, не страховой полис. Никаких «100% защиты» | да |
| Конкурент опустится | Продукт (аудит, кабинет, алерты) ему нечем повторить быстро; ручная себестоимость не пускает ниже ~3–4 тыс. | частично |

## 15. Фазы и гейты

| Фаза | Что | Гейт перехода |
|---|---|---|
| **1** | Самоаудит бесплатно + ручное закрытие пробелов | **≥50% дошли до конца аудита** |
| **2** | Монетизация: подписка, оплата вручную | **≥5 платящих** |
| **3** | Автоматизация повторившегося: кабинет, алерты, биллинг | retention ≥ 3 мес |
| **4** | Вторая ниша (ветеринария) | ниша закрыта **без нового кода** |
| **5** | Мультитенантность / white-label / другие юристы | 2-й юрист-партнёр |

**Гейт честности:** если на фазе 2 платящих нет — проблема в сегменте или в боли, а не в функциях.
Возврат к выбору сегмента, а не добавление модулей.

## Резюме

Продаётся состояние «в порядке перед регулятором», не документ. Сегмент — соло-медФОП (~35 тыс.),
верифицированно не обслуживаемый: ручные юрфирмы от 5–10 тыс. не спускаются вниз по экономике,
tech-продукты не покрывают медправо. Транзакционный спрос («оформи пакет») доказан рынком; подписочный
не доказан — бизнес строится на конверсии первого во второй, а мостом служит самоаудит, показывающий,
что пакет документов это снимок, а комплаенс — процесс. Масштабирование обеспечивает принцип
«услуга = данные»: doc-engine снимает производство документа, MCP+skills снимает интервью; новая ниша
должна закрываться конфигурацией. MVP = самоаудит (конфигурация + тонкий слой скоринга) + ручное
закрытие пробелов + ручная оплата; всё остальное сознательно не строится. Юрист — соавтор услуги, его
ёмкость защищена конструкцией продукта, а граница «диагностика можно / совет нельзя» — условие
существования продукта. Ключевой гейт: ≥5 платящих — иначе меняется сегмент, а не набор функций.
