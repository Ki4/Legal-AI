# Демо-сценарій для юриста — 1 липня 2026

> Мета: показати, що система робить **суд-готові документи надійно**, і як додаються
> нові послуги. ~10-15 хв. Усе живе (divorce/alimony на проді). Принципи — у
> `docs/strategy/how-it-works-onepager.md`.

## 0. Перед демо (чек, 5 хв зранку)
- [ ] ngrok піднятий (`pwsh scripts/dev-up.ps1`), n8n живий, бот відповідає.
- [ ] Тестовий прогін: `node scripts/test-webhook.mjs 2` → PDF+DOCX прийшли в Telegram.
- [ ] **Зберегти зранку** свіжі PDF+DOCX divorce+alimony — бекап, якщо живий прогін ляже.
- [ ] Відкриті вкладки: Telegram-бот · адмінка (`npm run dev:admin` :5174 або деплой) · one-pager.

## 1. Жива генерація (3 хв) — «документ за 30 секунд»
- У боті: «Розірвання шлюбу» → заповнити форму (поля заздалегідь готові).
- Submit → за ~30с приходять **два файли: PDF + DOCX** з підписом «✅ Ваш документ».
- Сказати: це **приватний файл**, не публічна ссилка; усі дані — з форми, нічого не «вигадано».

## 2. Чому це надійно (3 хв) — головний меседж
- LLM **не торкається** чисел / дат / ПІБ / сум — їх ставить детермінований шаблон.
- Чек-лист перевіряє обовʼязкові пункти на КОЖНІЙ генерації.
- Це відповідь на «а раптом ІІ помилиться»: на даних йому просто не дають помилятись.

## 3. Адмінка (4 хв) — як влаштована послуга
- Відкрити послугу → таб **«Документ»**: юрист бачить ТОЧНИЙ шаблон (де які дані стають).
- Таби «Анатомія / Граф звʼязків / Алгоритм форми»: структура, закони, логіка форми.
- Health-світло: чи узгоджені форма ↔ шаблон ↔ цитати.

## 4. Як додаються послуги (3 хв) — A/B/C/D + медицина
- Яруси (one-pager): **A/B** — детерміновано (юрист пише блоки), **C/D** — лише для складного аргументу / ескалація.
- **Медицина — наступний пілот** (детермінований пакет, реальні клієнти юриста).
- Питання до юриста: які документи; які частини детерміновані / потребують ІІ / ескалації.

## 5. Що треба від юриста після демо
- Sign-off по divorce **#67** (формулювання майно/борги — «вирішується окремим позовом»).
- Список **мед-документів** для пілота.
- Готовність валідувати майбутній authoring-інструмент (де юрист сам заводить блоки).

## Бекап-план (якщо живий прогін ляже)
ngrok/Google можуть відвалитись (див. `docs/runbooks/local-dev-startup.md`). Якщо бот не
відповідає — **показати збережені зранку PDF+DOCX** + превʼю в адмінці + one-pager.
**Принцип демонструється і без живого прогону** — головне не «магія», а детермінізм.
