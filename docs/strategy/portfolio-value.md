# Legal-AI как портфолио для AI Engineer

> Написано: 2026-05-15
> Контекст: оценка проекта относительно рынка труда AI-инженеров 2026-2027

---

## Ценность реального продакшн-проекта vs курсовых работ

**Один работающий продукт с реальными пользователями > десяти курсовых проектов.**

Курсы (IBM Generative AI Engineering, LangGraph на Udemy) дают словарь и фундамент.
Legal-AI дает **историю**: "я построил production систему генерации юридических
документов с LLM orchestration, vector search, и шифрованием данных."

Это разные вещи — они хорошо дополняют друг друга, а не заменяют.

---

## Что есть в проекте и чем это ценно для работодателя

| Что в проекте | Как это называется на рынке труда |
|---|---|
| n8n workflow + Groq/Gemini | LLM orchestration (аналог LangChain/LangGraph концептуально) |
| Supabase + pgvector | Vector database — прямое попадание в требования AI Engineer |
| AES-256-GCM шифрование PII | Security-conscious AI engineering |
| Hybrid template approach | **Зрелость: понимание когда НЕ использовать AI** |
| End-to-end: Telegram → Google Docs | Реальная production система, не туториал |
| Watched laws + CRON план | Production concerns: law drift = breaking changes |
| RLS + secret rotation runbook | Compliance и безопасность данных |

### Самое сильное: hybrid approach

Выбор НЕ генерировать документ полностью через AI (из-за рисков галюцинаций
в юридических текстах) — это архитектурное решение, а не упрощение.
Именно это отличает junior ("давай попросим GPT") от senior ("нет, вот почему шаблон надёжнее").

Это история, которую стоит рассказывать на интервью.

## Что добавит ценности в будущем

1. **README с архитектурой** — объяснить почему hybrid, а не full-AI.
   Это самая сильная история проекта.

2. **RAG для Tier 2** — когда придёт время:
   "built RAG system for legal document Q&A with pgvector + hybrid search"

3. **Переформулировать под LangChain-словарь** для резюме:
   - n8n = orchestration layer
   - Groq = LLM inference endpoint
   - pgvector = vector store
   - Supabase = managed PostgreSQL + vector DB

4. **Метрики после запуска**: документов сгенерировано, ошибок,
   среднее время генерации — конкретные цифры в резюме.

## Стратегия обучения рядом с проектом

**Не вместо проекта, а параллельно:**

| Ресурс | Зачем |
|--------|-------|
| IBM Generative AI Engineering (Coursera, аудит = бесплатно) | Системный фундамент + имя IBM в профиле |
| IBM RAG and Agentic AI (Coursera) | Современный стек: LangGraph, MCP — словарь для интервью |
| LangChain & LangGraph (Udemy, Eden Marco) | Практический код, проекты для GitHub |
| LangSmith | Логирование, отладка LLM-цепочек — отличает junior от senior |

**Приоритет**: сначала довести Legal-AI до реальных пользователей,
потом курсы — иначе курсы без контекста оседают хуже.

---

## Честная оценка

При цели Junior/Middle AI Engineer в 2026-2027:

- Legal-AI с реальными пользователями + курсы = **сильная позиция**
- Только курсы без проекта = слабая позиция (так у 80% кандидатов)
- Только проект без понимания экосистемы (LangChain/LangGraph терминология) = пройдет меньше интервью

**Ключевой milestone**: первые 10-20 реальных пользователей + зафиксированные метрики.
После этого проект становится кейсом, а не pet project'ом.
