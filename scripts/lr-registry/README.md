# lr-registry — анализ реестра лицензий МОЗ на медпрактику

Детерминированный пайплайн: сырая выгрузка реестра лицензий МОЗ → активные
субъекты → типизация (ФОП / частные юрлица / коммунальные) → ICP-сегменты →
агрегаты + лид-листы. Перезапускается на любой свежей выгрузке.

## Что где

- `analyze.py` — очистка, дедуп до субъекта, сегментация, reconciliation.
- `build_segments_xlsx.py` — сегментированный Excel (лид-листы) из `clean_entities.csv`.
- `aggregates/` — маленькие агрегаты в репо (регионы, специальности, годы,
  `summary.json` со сверкой). Сами лид-листы (`clean_entities.csv`, ~26 МБ) и
  сырой xlsx в репо **не коммитятся** (см. `.gitignore`).

## Запуск

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt

# 1. очистка + агрегаты (снимок = дата выгрузки)
./venv/bin/python analyze.py ЛР-10.04.2026.xlsx --outdir output --snapshot 2026-04-10

# 2. лид-листы Excel
./venv/bin/python build_segments_xlsx.py output/clean_entities.csv \
    --out lr-registry-segments.xlsx
```

## Важное про данные реестра

- Одна строка = **решение × место деятельности** (филиал), не субъект.
- `licence_id` — id решения, НЕ субъекта; один субъект = много licence_id.
- ЄДРПОУ/РНОКПП физлиц скрыт как `----------` → ФОП дедуплицируются по ФИО
  (полные тёзки схлопываются — небольшое занижение).
- Полностью аннулированные лицензии МОЗ, судя по составу выгрузки, удаляет из
  публичного реестра → история аннулирований в файле неполна (для неё — внешняя
  статистика, см. отчёт).
