# alimony-change — Plan

> **SDD-Tier 2** спека. Перша **T2-послуга** (гібридний документ) — пілот режиму `generation_mode='hybrid'`.
> Підхід, групи задач, послідовність. Контракт — `requirements.md`; перевірка — `validation.md`; робочий приклад з підсвіткою ризику — `example.md`.
> Концепція рівнів T1/T2/T3 і харнесс — `docs/research/service-tiers-and-ai-harness.md`.

## Послуга

**Зміна розміру аліментів** — позовна заява про **збільшення** (істець = одержувач) або **зменшення** (істець = платник) розміру аліментів, що вже присуджені рішенням суду / встановлені договором. Підстава — ст. 192 СК України (зміна матеріального/сімейного стану, стану здоров'я тощо).

Чому саме вона перша в T2 — `docs/research/service-tiers-and-ai-harness.md` §6: та сама база СК/ЦПК/ЗСЗ (граф переиспользується), тепла аудиторія alimony, і всі труднощі T2 в мінімальному обсязі (рівно один case-specific абзац + одна «плаваюча» величина + вхід = попереднє рішення суда), без «вибухової комбінаторики» поділу майна.

## Підхід

**Розширюємо doc-engine, а не будуємо паралельний пайплайн.** Скелет документа — той самий декларативний шаблон (`generation_mode` отримує третє значення `hybrid`); новизна лише в **одній секції** (обґрунтування зміни обставин), яку шаблон не може зібрати, і в **обв'язці навколо неї** (retrieval → constrained generation → критики → abstention → пакет юристу).

**Порядок виправдання ризику** (дзеркало doc-engine):
1. **L1 скелет офлайн** — шаблон `alimony-change.document.txt` без секції L3 → parity/golden на детермінованих гілках (напрямок ↑/↓, судовий збір, реквізити). Доводиться як звичайна T1-послуга у vitest, **до будь-якого LLM**.
2. **L2 retrieval офлайн** — eval-набір «ситуація → очікувані норми» проти `law_relations` (seed ст.192 СК). Жодного LLM у проді: граф — dev-задача (ярус 1–2 авто, ярус 3 — ревью юриста).
3. **L3 reasoning + L4 критики** — підключаємо **на безкоштовному Groq (JSON-mode + enum)**; abstention за замовчуванням → якщо якість не дотягує, документ іде чистим шаблоном (поведінка не гірша за T1). Claude API — тільки якщо court-ready проза на Groq не дотягне.
4. **L5 handoff** — review-card + підсвітка; вмикається разом з L3.

Кожен крок реверсивний: міграція `hybrid` нічого не вмикає (default `'js'`); послуга живе `disabled`, поки юрист не підтвердить ярус-3 граф.

## Групи задач

### G1 — Скелет (детермінований, без LLM)
- `n8n/templates/services/alimony-change.document.txt` — шаблон doc-engine: шапка, сторони, **посилання на попереднє рішення** (суд, № справи, дата, поточний розмір/спосіб), процесуальні заяви (ст.175 ЦПК), `ПРОШУ` (змінити з X на Y), додатки, підпис. Секція обґрунтування — поки **плейсхолдер `{{reasoning}}`** з generic-fallback (абзац ст.182, як в alimony).
- **Детерміновані гілки** (юридично-критичні — у шаблоні/хелперах, тестуються 1 раз):
  - напрямок `change_direction` (`increase`|`decrease`) → хто позивач/відповідач, текст прохання, додатки;
  - **судовий збір — гілка за напрямком:** `increase` → звільнення (п.3 ч.1 ст.5 ЗСЗ); `decrease` → розрахунок (хелпер `courtFee`, див. requirements §3.4) з `registry`-величини прожиткового мінімуму;
  - спосіб аліментів `alimony_type` (percent/fixed) — як в alimony.
- `form_config` для послуги (нові поля — requirements §1) + реєстрація в каталозі (`disabled`).
- Parity/golden-тести скелета (без L3).

### G2 — Граф норм (L2, dev-задача, ярус 1–3)
- Seed `law_chunks` статтями кластера: СК 141,150,180,182,183,184,**191,192**; ЦПК 28,**176**,175,177; ЗСЗ ст.4, ст.5.
- Migration `law_relations` (схема — `GRAPHRAG-GUIDE.md`) + рёбра під послугу:
  - `192 → 182 (requires)` — суд враховує обставини ст.182;
  - `192 → 183/184 (clarifies)` — спосіб (частка/тверда);
  - `decrease → ст.4 ЗСЗ (exception_if: change_direction==decrease)` — платиться збір; `increase → п.3 ч.1 ст.5 ЗСЗ (exception_if: increase)` — звільнення;
  - `ціна позову → ст.176 ЦПК (requires)`.
- Ярус 3 (exception_if + логіка) — **pending до ревью юриста** (Оля). Eval-набір retrieval (validation §G2).

### G3 — Reasoning + критики (L3+L4)
- `n8n/prompts/alimony-change-reasoning.txt` — промпт генерації обґрунтування: вхід = факти-зміни (enum) + норми L2; **strict structured output**: цитувати лише `article_id ∈ L2`; заборона вводити числа/дати/ПІБ, яких немає у вході.
- `n8n/templates/groundedness.js` — **критик-1 (без LLM):** кожне число/дата/№/ПІБ у прозі ∈ L0 verbatim; кожна цитата ∈ L2 → інакше span RED.
- `n8n/prompts/alimony-change-critic.txt` — **критик-2 (LLM, незалежний прохід):** groundedness per-sentence → spans + confidence (AMBER нижче порога).
- **Abstention:** критики провалені → `{{reasoning}}` = generic-fallback + алерт (Error Trigger).

### G4 — Handoff + n8n інтеграція (L5)
- Розширити dispatch Build Document: `generation_mode === 'hybrid'` → L1 шаблон з вставленою (або abstained) секцією L3.
- `review-card` (JSON, requirements §5) у відповідь + 🟡-коменти в Google Docs (`batchUpdate`).
- Деплой form-submit; live e2e на фікстурах ДО будь-якого флипу; послуга лишається `disabled`.

### G5 — Доки + закриття
- `DECISIONS.md` — рішення: режим `hybrid` як розширення dispatch; межа детермінізму; розташування критиків; abstention-контракт.
- `IMPROVEMENTS.md` — «вибухова комбінаторика» поділу майна як друга T2-ітерація; admin-редактор reasoning-промпта.
- `specs/roadmap.md` — v2.1/2.3: пілот hybrid закрито.
- `docs/research/service-tiers-and-ai-harness.md` — звірити з реалізацією.
- changelog + session-summary; `Closes #N` при merge.

## Послідовність і чекпоінти

```
G1 ─────► G2 ─────► G3 ─────► G4 ─────► G5
скелет     граф       LLM        handoff   доки
(vitest)   (dev,      (Groq,     (live,
           ярус3=     abstention disabled)
           pending)   default)
   └─ L1 доводиться як T1-послуга ДО появи LLM;
      reasoning вмикається лише коли critics+abstention зелені;
      послуга йде в прод тільки після ярус-3 ревью юриста.
```

**Стоп-умова.** Якщо на G3 abstention-rate на eval-наборі стабільно високий (проза не проходить критиків) — це **не баг, а сигнал**: court-ready обґрунтування цієї послуги поки не автоматизується надійно → лишаємо чистий шаблон (фактично T1-документ «зміна розміру» без багатої мотивації) і виносимо reasoning у backlog.
