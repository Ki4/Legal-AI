## Edge cases (обов'язково)

- [ ] `decrease` з крихітною різницею → судовий збір = підлога 0.4 ПМ (не 1%)
- [ ] `cost_of_living_up` як **єдиний** `changed_fact` → ⚠️ обґрунтування НЕ має зводитись до «підняли мінімум законом» (ст.192: зміна закону ≠ підстава); критик-2 ловить таке як AMBER
- [ ] `prior_alimony_type=percent` → `requested=fixed` (без даних про дохід): `monthly_delta` невідома → ціну позову заповнює юрист, review-card ставить питання (requirements §7)
- [ ] Декілька дітей різного віку → 50%-підлога рахується per-age
- [ ] Порожній/суперечливий `changed_facts` (напр. одночасно `payer_income_up`+`payer_income_down`) → валідація форми блокує
- [ ] L3 LLM недоступний (Groq 5xx) → abstention, документ виходить чистим шаблоном

## Definition of Done

Користувач подає форму «зміна розміру аліментів» (↑ або ↓) → отримує **юридично коректний скелет документа з детермінованим розрахунком судового збору за напрямком**; case-specific обґрунтування або згенероване **під enum-констрейнтом і двома критиками**, або (за abstention) відсутнє без шкоди для валідності; юрист отримує **review-card з підсвіченими 🟡-секціями і конкретними питаннями**, а не «весь документ заново». 🔴 у виданому документі неможливі конструктивно. Послуга вмикається в прод **тільки після ярус-3 ревью юриста** (`status='active'`).
