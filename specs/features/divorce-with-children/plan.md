# divorce-with-children — Plan

> **SDD-Tier 2** спека. Refs issue [#28](https://github.com/Ki4/Legal-AI/issues/28).
> **НЕ нова послуга.** Розширення існуючої `divorce` — базовий кейс "є діти" (місце проживання / спір→окреме провадження / аліменти) вже живий. Контракт — `requirements.md`; перевірка — `validation.md`.

## Послуга

Розширення позовної заяви про розірвання шлюбу для випадку, коли в сторін є спільні неповнолітні діти. Два нових елементи, яких зараз немає:

1. **«Суд визначить» як варіант місця проживання дітей** (поряд із «зі мною» / «з відповідачем» / «частково з кожним», що вже є).
2. **Графік участі у вихованні та спілкуванні з дитиною** того з батьків, хто проживає окремо (ст. 157 СК України) — окремо від питання місця проживання.

Чому вузько: при скоупінгу (session 32, коментар до issue #28) виявилось, що 3 заявлені залежності issue (#19 GraphRAG-таблиця, #17 hybrid-шаблони, стабільна послуга аліментів) вже закриті інфраструктурою, збудованою для `alimony-change` (сесії 20–29), а сама "опіка" в укр. праві — не окремий інститут для дітей з батьками (це для дітей без батьківського піклування), а саме право участі у вихованні/побачень. Те, що реально лишається новим — два пункти вище.

## Підхід

**Чисто детерміновано — без LLM, без графа, без нового `generation_mode`.** Підтверджено з Сергієм (session 32): графік побачень при спорі → «вирішуватиметься в окремому провадженні» (як вже працює `children_dispute` для місця проживання), без AI-обґрунтування. Це той самий doc-engine `generation_mode='template'`, яким `divorce` вже живе — змінюються лише форма (`divorceFormConfig.ts`) і шаблон (`divorce.document.txt`), без migration, без нових n8n-нод.

Головний ризик — не юридична складність (вона помірна), а **регресія 263 існуючих parity-тестів** `divorce-template-parity.test.js`: шаблон вже має нетривіальну if-ланцюжкову нумерацію пунктів «ПРОШУ» (5→8 залежно від наявності аліментів/майна/боргів), і новий пункт (графік побачень) вставляється в середину цього ланцюжка.

## Групи задач

### G1 — Форма + шаблон (детерміновано)
- `apps/client/src/data/divorceFormConfig.ts`:
  - `children_live_with` — додати опцію `court` («Визначить суд»).
  - НОВЕ `visitation_dispute` (choice: `none`/`separate`) — `show_if: { any: [children_live_with=='plaintiff', children_live_with=='defendant'] }` (графік стосується лише випадку, коли один із батьків має основне місце проживання дитини; при `'both'`/`'court'` питання поки не актуальне — §5 requirements).
  - НОВЕ `visitation_schedule_text` (textarea) — `show_if: { all: [<та сама residence-умова>, visitation_dispute=='none'] }`.
- `n8n/templates/services/divorce.document.txt`:
  - `children_live_with` if-ланцюжок (зараз `plaintiff`/`defendant`/`both`) — додати `else if children_live_with == 'court'`.
  - Новий абзац (поряд з існуючим «Спір щодо місця проживання...», §requirements 2.2): узгоджений графік (з тексту поля) або «спір… в окремому провадженні».
  - Новий пункт «ПРОШУ» (графік побачень, якщо узгоджений) — вставляється між існуючим пунктом 5 (місце проживання) і пунктом аліментів; **усі downstream номери (аліменти/майно/борги) перераховуються** — найризикованіша частина зміни.
- `scripts/upload-document-template.mjs divorce` + `node scripts/update-form-configs.mjs` — заливка (після live-перевірки, не раніше G3).

### G2 — Тести (parity, без LLM)
- Нові parity-кейси: `children_live_with='court'`; `visitation_dispute='none'` з текстом графіка; `visitation_dispute='separate'`; матриця сумісності з існуючими аліменти/майно/борги (перевірка перерахованих номерів).
- **Регресія: усі 263 існуючих тести `divorce-template-parity.test.js` лишаються зеленими без модифікації очікуваних виводів** (нові поля `undefined` у старих фікстурах → нова секція не рендериться, нумерація не змінюється).

- Live: upload form_config + template (як divorce-template-port, session 21) → smoke-тест 1 сценарій з графіком → перевірка існуючих сценаріїв (regression).
