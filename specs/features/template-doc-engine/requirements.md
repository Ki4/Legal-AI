# Template Document Engine — Requirements (Tier 2)

**Статус:** DRAFT (spec из /interview, 2026-07-13). Не в работе.
**Slug:** `template-doc-engine`
**PoC-основа:** валидирован end-to-end (см. `[[project_docx_engine_poc]]`, папки `poc-dogovir/`, `poc-alimony/`).

## Проблема (WHY)

Сегодня каждая новая юр-услуга = отдельный кусок кода в MCP, который пишут и верифицируют
разработчики. Юрист (Ольга) не самодостаточна — она в связке с нами на каждый документ.
Это узкое место масштабирования каталога услуг.

## Цель

Отдельный **Python-движок** генерации украинских юр-документов, где:
- юрист авторит шаблон в обычном Word + размечает поля/условия в веб-панели;
- **схема полей и ветвлений выводится из шаблона** (шаблон = единственный источник правды);
- один общий движок + N шаблонов заменяет N захардкоженных MCP-тулов;
- добавление услуги = добавление шаблона (данные), а не кода.

## Скоуп (что ВХОДИТ)

Полный вертикальный срез, три фазы (каждая со своей проверкой):

**Фаза A — Ядро движка**
- `template.docx` ({{поля}}, `{%tr%}` цикл, `{%p if%}` условие, `keep_with_next` подпись) + JSON → `.docx` → PDF (Gotenberg).
- Склонение ФИО — **каскад**: pymorphy3 → LLM-фолбэк → флаг HITL; пополняемая библиотека проверенных форм.
- Даты прописью (date-to-words), preflight (все `{{поля}}` имеют данные и наоборот).
- **Один реальный шаблон целиком: аліменти.**

**Фаза B — Авторский поток**
- Юрист загружает `.docx`, **выделяет** переменные → система генерит имя/тип/схему поля.
- Юрист выделяет блок → **AI предлагает условие** из уже помеченных полей → юрист подтверждает.
- Авто-деривация схемы из шаблона; preflight-превью (заполнить тест-данными → показать PDF).
- Флаги неуверенного склонения: **инлайн-маркер в превью + список сверху** (см. §HITL).

**Фаза C — MCP-интеграция**
- Один generic тул `generate_document(послуга, дані)` — подхватывает нужный шаблон.
- Архитектурно «услуга = **список** шаблонов» (мульти-документ), реализовать пока 1 док.

## Вне скоупа (явно)

- Batch-режим (один шаблон × много клиентов) — НЕ нужно.
- Word-плагин/Office-надстройка — НЕ делаем (склонение серверное, не в Word).
- Миграция дядиного MCP (`declension.ts` + Groq) — **не трогаем**, отдельный трек.
- Реальная мульти-документная генерация (>1 док на услугу) — только архитектурный задел.
- Форма как источник JSON — вторичный путь, тот же формат; основной = диалог с агентом.

## Ограничения / решения

- **Отдельный Python-сервис** (движок на docxtpl/pymorphy3) — граница языка с Node/TS
  (`mcp-server`, `admin`). Движок = FastAPI-сервис, MCP/админка зовут по HTTP. Gotenberg = Docker.
- Шаблоны + выведенная схема + библиотека склонений — в **Supabase** (в духе `form_config`).
- Авторская панель — расширение `apps/client/src/admin` (Service Builder), не новое приложение.
- Документ всегда «ЧЕРНЕТКА — потребує перевірки юриста» до подписи Ольги.
- JSON основной источник — **интерактивный диалог с агентом** (текущий MCP+skill поток).

## HITL — склонение (юр-критично, DEMO-FINDINGS «B»)

Каскад надёжности:
1. pymorphy3 (gender-aware по по-батькові) склоняет;
2. если нет разбора / Fixd-подозрение / пробел словаря → **LLM-фолбэк** (Groq/Claude);
3. если и LLM неуверен → **флаг Ольге**: инлайн-маркер в превью + список «проверь N».
4. Подтверждённые Ольгой формы → **пополняемая библиотека** (Supabase) → в следующий раз известны.

Движок НИКОГДА не подставляет склонение тихо: неуверенное всегда помечено.

## Критерий «готово» (измеримый)

Parity + автопроверки + человек (≥2 согласующихся свидетельства, `VERIFICATION-PROTOCOL`):
1. **Parity:** движок на данных из `generate_alimony_document` даёт документ, текстово
   эквивалентный эталону MCP (± улучшения дат) — автоматический diff-тест.
2. **Автопроверки зелёные:** склонение = эталон (4 падежа), условные блоки сработали,
   плейсхолдеров нет, подпись не разорвана (тест пагинации через Gotenberg).
3. **Подпись Ольги:** 1 реальный алиментный документ подтверждён юристом как court-ready.

## Открытые вопросы (для impl-чата)

- Точная схема хранения в Supabase (таблица templates + bucket + schema JSON + dictionary).
- Транспорт движок↔MCP (HTTP REST vs что-то ещё), где хостится Python-сервис.
- Формат разметки полей юристом в UI (выделение → как хранится маппинг в docx).
- LLM для фолбэка склонения: Groq (как у дяди) или Claude API.
