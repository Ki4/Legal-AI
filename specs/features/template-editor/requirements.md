# template-editor — Requirements

> Контракт фічі (Tier 2). Редактор шаблона документа для юриста в адмінці — конвеєр 3 сесій.
> Ця спека покриває ВЕСЬ конвеєр; сесія 1 реалізує §1–§3 (ядро), сесії 2–3 — §4–§5.
>
> 🔗 Контекст: план-дослідження (interview 2026-07-02, 12 питань), `docs/strategy/service-builder-vision.md`,
> фіча `document-layout-preview` (#84, реюз), IMPROVEMENTS #51 (редактор шаблону — closes),
> ринкове дослідження: side-by-side DSL+тулбар+прев'ю (APITemplate/XpressDox-модель; WYSIWYG відхилено —
> жоден ринковий WYSIWYG не виражає умовну логіку, round-trip DSL↔дерево крихкий).

## §0. Намір (одним абзацом)

Ольга (юрист) і Сергій редагують текст шаблона документа (`services.document_template`) прямо в
адмінці — з тулбаром стилів (по центру / праворуч / жирний / відступ / з нової сторінки / тримати
разом), палітрою змінних, кнопками-скелетами логіки та живим прев'ю (Документ + A4-Розкладка) — без
SQL. Правки безпечні для проду: пишуться в **чернетку**, бот генерує за **опублікованою** версією,
публікація проходить парс-гейт і лишає снапшот в архіві ревізій (`service_revisions`) з відновленням.

## §1. Модель даних (сесія 1)

- `services.document_template_draft TEXT NULL` — чернетка. `NULL` = чернетки нема (редактор показує
  опубліковану версію як стартовий текст). Бот/n8n **ніколи** не читає draft.
- `service_revisions` — append-only архів снапшотів усієї послуги:
  `{ id, service_id, snapshot JSONB, changed_by UUID, reason TEXT, created_at }`.
  `snapshot` = повний рядок services (title, slug, form_config, ai_prompt, document_template,
  document_template_draft, status, price, icon, description, generation_mode).
  Пишеться: перед публікацією шаблону (`reason='publish_template'`), перед відновленням
  (`reason='restore'`); майбутнє (сесія 3+): перед великими правками/видаленням.
- RLS: обидва об'єкти — тільки authenticated admin (як `services`); анонім не бачить draft і ревізії.

## §2. Ядро редактора (сесія 1)

### §2.1 Вкладка «Шаблон» у ServiceEditPage
- Четверта вкладка поряд із Форма / AI / Налаштування. Порядок: Форма · Шаблон · AI · Налаштування.
- Ліва панель: `<textarea>` (моношрифт) з draft-текстом; лічильник змін (dirty-маркер як у формі).
- Кнопки: **«Зберегти чернетку»** (пише draft; працює ЗАВЖДИ, навіть із парс-помилкою — не втрачати
  роботу) і **«Опублікувати»** (парс-гейт → снапшот у ревізії → `document_template = draft`).
- Статус-рядок: «Чернетка відрізняється від опублікованої» / «Опубліковано» / парс-помилка.

### §2.2 Парс-гейт (публікація)
- Валідація через РЕАЛЬНИЙ рушій (`@doc-engine` → `renderDocumentWithStyles` на sample/порожніх
  answers, як `renderPreview`): помилка парсера (незакритий `{{#if}}`, кривий тег) → публікація
  **заблокована**, повідомлення українською простою мовою + рядок помилки рушія.
- Невідома змінна (нема ні у form_config, ні в білому списку обчислюваних полів рушія) → **жовте
  попередження** зі списком, НЕ блок (сесія 2 UI-панель; у сесії 1 — мінімальний список під textarea).

### §2.3 Прев'ю (права панель, desktop)
- Таби «Документ» (`DocumentPreview`, дефолт) / «Розкладка» (`DocumentLayoutPreview`) — обидва
  рендерять **draft** (що бачу = що опублікую). Реюз компонентів як є (props `template`, `slug`).
- Мобільний/планшет: read-only прев'ю + напис «Щоб редагувати шаблон — зайдіть з комп'ютера»
  (повний адаптив → IMPROVEMENTS).

## §3. Безпека проду (інваріанти сесії 1)

1. **Бот читає лише `document_template`** — жодна зміна draft не впливає на генерацію до публікації.
2. **Публікація неможлива з парс-помилкою** (гейт на реальному рушії, не на копії правил).
3. **Кожна публікація лишає снапшот** у `service_revisions` (аудит: хто/коли/що).
4. **Рушій не змінюється** (`render-document.js` — SSoT, тільки читаємо).

## §4. Зручності (сесія 2 — 3 незалежні шматки, паралельні агенти)

- **(а) Тулбар:** кнопки стилів вставляють `{{!style: …}}`-рядок перед поточним абзацом
  (`insertAtCursor`-утиліта, курсор зберігається); «Тримати разом» обгортає виділення
  `{{!style: keep-block}} … {{!style: /keep-block}}`; кнопки логіки вставляють валідні скелети
  `{{#if поле}}…{{/if}}` / `{{#each children}}…{{/each}}`.
- **(б) Палітра змінних:** поля з form_config (укр. label + id) + обчислювані поля рушія (білий
  список з `buildContext`: `plaintiff_name`, `defendant_name`, `children`, `court_fee`, `ai.*` тощо);
  клік вставляє `{{field}}`; бейджі «не в шаблоні / бракує» з готового diff (`serviceAnatomy`).
- **(в) Чипи у прев'ю:** третій режим «Показати змінні» — незаповнені `{{field}}` рендеряться сірим
  чипом з укр. label (digitalved-паритет) + панель валідації. UI-шар, рушій не чіпати.

## §5. Блоки Фаза 0 + каркас + історія (сесія 3)

- Read-only мітки блоків у прев'ю (кольори/label з `blockRegistry`, `detectBlocks` по відрендереній
  чернетці; при парс-помилці мітки чесно гаснуть).
- «Створити з каркаса» для послуг без шаблону: НЕобов'язковий скелет позовної заяви (8 канонічних
  блоків зі стилями і keep-block); `generation_mode='template'` при першій публікації.
- «Історія змін»: список `service_revisions` + «Відновити» (відновлення теж пише ревізію).

## §5b. S2-конвеєр — «полу-WYSIWYG над DSL» (сесії 67+, доповнення 2026-07-03)

> База: ресёрч `apps/client/.claude/reports/2026-07-03-editor-{ux-analysis,architecture-research}.md`.
> Вердикт: CodeMirror 6 (документ = DSL-рядок, декорації чисто візуальні) + styleHints v2 «runs»
> (єдине перенесення з OOXML). Повний WYSIWYG (round-trip) відхилено втретє.

- **(A) CodeMirror 6 swap** (сесія 67): textarea → CM6; підсвітка DSL за типом тега (змінна /
  логіка / style-директива / коментар — патерн HotDocs); `{{поле}}` → атомарний чип з укр. label
  із form_config (курсор всередині/поруч → сирий тег, патерн Obsidian Live Preview); каретка-гейт
  і тулбар/палітра працюють як раніше (той самий контракт applyEdit).
- **(A2, сесія 68):** іконки-віджети замість `{{!style:…}}` рядків · fold умовних блоків +
  кольорова смуга `{{#if}}`-діапазонів.
- **(B) styleHints v2 «runs»** — інлайн-стилі в рушії (`{{#bold}}…{{/bold}}`, offsets ПІСЛЯ
  підстановки змінних через sentinel; Google Docs `updateTextStyle` по спадних індексах).
  ⚠️ Legally-critical: АДИТИВНО, старі шаблони байт-у-байт, parity-тести лишаються зеленими +
  нові на runs. Окрема сесія, не поспішати.
- **(C) полірування:** sync-підсвітка «каретка ↔ абзац превʼю» (маппінг рядок↔абзац рушій уже знає).

**Інваріанти S2:** (1) DSL-текст = єдиний SSoT, редактор НЕ має (де)серіалізатора; (2) декорації
не мутують текст — найгірший збій = негарно показало, текст цілий; (3) рушій чіпає лише слайс B,
адитивно; (4) контракт панелі (draft/publish/гейт/історія) незмінний.

## §6. Поза скоупом (явно)

- ❌ WYSIWYG / Tiptap / round-trip DSL↔дерево (відхилено дослідженням).
- ❌ UX-злиття ServiceViewPage/ServiceEditPage — окремий трек після конвеєра.
- ❌ Блоки Фаза 1–2 (per-block тумблери, блочний редактор, variant-групи, dependency) — окрема
  Tier-2 спека + sign-off Ольги.
- ❌ Повний мобільний адаптив редактора (→ IMPROVEMENTS).
- ❌ Зміни у n8n-потоці генерації; зміни рушія; клієнтський live-конструктор.
- ❌ Каркаси для інших типів документів (заява/клопотання) — блочний трек.

## §7. Інваріанти (весь конвеєр)

1. Один рендерер (`@doc-engine`) для гейта, прев'ю і продової генерації — нульовий дрейф.
2. Draft-у-БД, а не в localStorage: Ольга і Сергій бачать одну чернетку з різних машин.
3. Кожна руйнівна дія (публікація, відновлення, майбутнє видалення) — снапшот до дії.
4. UI українською, помилки — простою мовою (цільовий користувач — юрист, не розробник).
